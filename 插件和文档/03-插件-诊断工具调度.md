# ③ 诊断工具调度插件（only-u-diagnose-tools）

## 1. 概述

功能域：**第三方诊断/硬件检测工具调度**。调度 MIT 协议的诊断类工具（进程/驱动级监控、硬件细节报告等）——只补 01 内置诊断够不着的能力（ADR-0007：PowerShell 够得着就不引入第三方工具）。

- 包名：`only-u-diagnose-tools`
- 开发状态：**已实现**（调度框架代码完成，见 `插件文档\插件\only-u-diagnose-tools\`；工具收录待逐条 CLI 实测，实测前知识库为空 = 不可调度）
- 插件形态：标准 dsh.bundle 包，注册工具 `diag_tool_list` / `diag_tool_run`

## 2. 构成

```
plugins\only-u-diagnose-tools\
  package.json  cordis.patch.yml  index.js
  lib\
    catalog.js                  # 知识库 → 运行期目录（包内 tools\ 解析 + schedulable 判定）
    runner.js                   # 执行器（shell:false + 超时杀树 + 结果文件轮询 + 退出码）
    exitcodes.js                # 退出码 → 含义
  knowledge\
    diagnose-tools.json         # 生效知识库（空 = fail-closed）
    candidates.diagnose.json    # 候选：System Informer / Diag / WindowsDiagnostic / MultiDiagToolkit（待实测）
    README.md                   # 收录流程说明
  tools\                        # MIT 工具二进制随包分发（当前为空；收录后每个工具一个子目录 + LICENSE）
```

## 3. 应用场景

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 深度进程/驱动排查 | 01 内置诊断看不出问题 | 调度 System Informer 类工具做进程/驱动级深度检查 |
| B 硬件细节报告 | 需要电池/GPU 等细节信息 | 调度硬件检测工具导出报告 |
| C 验机增强 | 二手电脑验机，01 报告不够细 | 在 01 报告基础上补充第三方检测结果 |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「深度进程/驱动排查」**
> 内置诊断没发现明显问题，帮我列出可用的第三方深度检测工具并说明各自作用，选最合适的做一次只读检查。

**场景 B「硬件细节报告」**
> 我需要电池和 GPU 的详细信息，帮我看看有哪些硬件检测工具可用，执行前先说明要跑什么。

**场景 C「验机增强」**
> 先跑内置诊断（ops_diagnose），再列出第三方检测工具，如果内置报告已覆盖就不用重复跑了。

## 5. 使用方法

1. 用户描述需求 → 模型先判断 01 内置诊断是否够用。
2. 不够用 → `diag_tool_list` 列工具 → `diag_tool_run({ tool, params })` 执行（写盘/压测类条目弹确认条）→ 结构化结果整理成结论。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-diagnose-tools
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-diagnose-tools`。

## 7. 开发要点

### 7.1 已实现（调度框架）

- 框架四模块（catalog/runner/exitcodes + index.js 注册 `diag_tool_list`/`diag_tool_run`）已落地，与 04/05 两插件**各带副本**（零依赖、包自足原则）。
- 收录条目 `tier: green`（只读信息导出）不弹确认条直接跑；`tier: red`（写盘/压测）先 `approval.request` 确认。
- exe 一律从包内 `tools\` 解析（工具随包分发，不依赖用户已装软件）。
- 配置与超时：`cordis.patch.yml` 配置键 `pollTimeoutMs: 10000`（结果文件轮询等待上限）；`diag_tool_run` 工具级 `timeoutMs: 1800000`（上限，单工具实际超时取知识库条目 `timeoutMs`，当前候选 300000）。知识库条目字段：`argTemplate`（参数模板，仅 `${key}` 填充）、`outPattern`（结果文件路径模板）、`exitCodes`（退出码→含义）、`maxOutBytes: 524288`（输出截断上限）。
- ✅ 接线冒烟通过（空库→空目录、未知工具抛错、fillTemplate 注入安全、候选 `verified:false` 不可调度；测试脚本 `temp\smoke-test-wiring.mjs`，2026-08-23）。

### 7.2 工具收录（剩余任务）

候选 4 款（`knowledge\candidates.diagnose.json`，全部 MIT，未验证前不可调度）：

| 工具 | 仓库 | 定位 | 收录注意 |
|------|------|------|----------|
| System Informer | winsiderss/systeminformer（15.7k star，活跃） | 进程/驱动级监控 | 首选；只调度信息查看，不开放结束进程能力 |
| Diag | MOSFET111/Diag | 硬件检测报告导出 | 待实测报告导出参数 |
| WindowsDiagnostic | LukeOnuke/WindowsDiagnostic | 轻量组件检测 | 与 01 重叠度高，需论证增量价值 |
| MultiDiagToolkit | Jackstar1212/MultiDiagToolkit | 多合一诊断 | 同上 |

收录流程：实测 CLI（静默参数/报告导出/退出码）→ 填 `audit.cliEvidence` → 二进制 + LICENSE 进 `tools\<id>\` → 条目改 `verified: true`、`schedulable: true` 移入 `diagnose-tools.json`。**只收宽松协议（MIT/BSD/Apache-2.0/Unlicense/zlib），GPL/MPL 等传染性协议一律不收录。**

## 8. 与 01 内置诊断的分工

| | 01 内置诊断（ops_diagnose） | 本插件（diag_tool_*） |
|---|---|---|
| 能力 | PowerShell 可达：磁盘/内存/事件/SMART 摘要 | PowerShell 不可达：进程驱动级、硬件细节报告 |
| 依赖 | 零依赖，无网可跑 | 工具随包分发（收录后） |
| 触发顺序 | 默认先跑 | 内置不够用才上 |
