# ⑩ 硬件监测插件（only-u-hw-monitor）

## 1. 概述

功能域：**硬件监测（综合硬件信息 / CPU / GPU / 电池）**。内置两个只读快查脚本（电池健康、NVIDIA GPU）+ 调度宽松协议的第三方监测工具。对标图吧工具箱「综合检测」分类（图吧工具箱主程序、CPU-Z、GPU-Z、BatteryInfoView 等）的只读信息能力。

- 包名：`only-u-hw-monitor`
- 开发状态：**已实现**（内置快查可直接用；调度框架完成，工具收录待实测）
- 插件形态：标准 dsh.bundle 包，注册工具 `mon_tool_list` / `mon_tool_run` / `mon_battery_report` / `mon_nvidia_smi`
- 与 01/03 分工：01 只管 PowerShell 可达摘要；03 管进程/驱动级；本插件管**硬件细节信息**（电池/GPU 温度/综合清单）——能力互补不重复

## 2. 构成

```
plugins\only-u-hw-monitor\
  package.json  cordis.patch.yml  index.js
  lib\
    catalog.js   runner.js   exitcodes.js   # 调度框架（各带副本，包自足）
    runScript.js                            # 内置脚本执行器（与 01 同构）
  assets\
    battery-report.ps1   # 电池健康报告（powercfg /batteryreport + 解析摘要）
    nvidia-smi.ps1       # NVIDIA GPU 快查（调用系统 nvidia-smi，不随包分发 NVIDIA 组件）
  knowledge\
    hw-monitor-tools.json       # 生效知识库（空 = fail-closed）
    candidates.hw-monitor.json  # 候选：fastfetch / WindowsHardwareInfo / nwinfo / Intel PCM（待实测）
    README.md
  tools\                        # 工具二进制随包分发（当前为空）
```

## 3. 应用场景

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 电池健康检查 | 续航骤降、电池不耐用 | mon_battery_report 只读快查（健康度/循环次数） |
| B GPU 状态快查 | 怀疑显卡过热/满载 | mon_nvidia_smi 只读快查（温度/利用率/显存/功耗） |
| C 综合硬件清单 | 验机、装机清单 | mon_tool_run（fastfetch JSON 导出等，收录后） |
| D CPU 温度监测 | Intel 平台要温度/功耗 | mon_tool_run（Intel PCM，red tier + 确认门，收录后） |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「电池健康」**
> 帮我查一下电池健康度，只读检测就行，把设计容量、实际容量、循环次数告诉我。

**场景 B「GPU 状态」**
> 帮我看看显卡现在什么状态：型号、温度、利用率、显存占用、功耗。

**场景 C「综合硬件清单」**
> 帮我出一份这台电脑的硬件清单（CPU/主板/内存/显卡/显示器），先用内置工具，不够细再列第三方工具。

## 5. 使用方法

1. 电池/GPU 快查：直接调 `mon_battery_report` / `mon_nvidia_smi`（只读，不弹确认）。
2. 深度需求 → `mon_tool_list` 列工具 → `mon_tool_run({ tool, params })`；条目标注风险（如 Intel PCM 加载驱动）先弹确认条。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-hw-monitor
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-hw-monitor`。

## 7. 开发要点

### 7.1 已实现

- **内置快查 2 个（可用）**：`mon_battery_report`（powercfg /batteryreport 解析摘要：型号/设计容量/完全充电容量/健康度/循环次数）、`mon_nvidia_smi`（`nvidia-smi --query-gpu=... --format=csv`，无 NVIDIA GPU 时返回提示而非报错）。两者均只读、走 `lib\runScript.js`（UTF-8 解码 + 超时杀树）。
- **调度框架**：与 03 同构副本，`mon_` 前缀。tier 规则同其他调度插件（green 直跑 / red 确认门 / 无审批服务 fail-closed）。
- 配置与超时：`pollTimeoutMs: 10000`；`mon_tool_run` 工具级 `timeoutMs: 1800000`（上限，单工具实际超时取条目 `timeoutMs`，当前候选 60000/120000）。
- ✅ 接线冒烟通过（2 内置工具注册成功、空库→空目录、候选不可调度；测试脚本 `temp\smoke-test-wiring.mjs`，2026-08-23）。

### 7.2 工具收录（剩余任务）

候选 4 款（`knowledge\candidates.hw-monitor.json`）：

| 工具 | 仓库 | 定位 | tier | 收录注意 |
|------|------|------|------|----------|
| fastfetch | fastfetch-cli/fastfetch（MIT，24.3k★） | 综合硬件清单（--format json） | green | 首选 |
| WindowsHardwareInfo | GitHub（MIT，141★） | 硬件清单导出 | green | 备选 |
| nwinfo | ncruces/nwinfo（Unlicense，676★） | 分域硬件信息 | green | 备选 |
| Intel PCM | intel/pcm（BSD-3-Clause，3.3k★） | CPU 温度/功耗/带宽 | red | 需管理员 + MSR 驱动；Intel 限定 |

收录流程与其他调度插件相同（实测 CLI → `audit.cliEvidence` → 二进制 + LICENSE → `verified: true` 移入生效库）。**只收宽松协议；GPL/MPL 一律不收录。**

### 7.3 诚实缺口（协议边界所致）

- **AMD CPU 温度、主板风扇/电压**：无宽松协议的内核驱动方案（LibreHardwareMonitor 为 MPL-2.0，按队长批准的协议边界排除）。文档化缺口：遇此类需求引导 BIOS/厂商工具手动查看。
- **内存时序**：无宽松协议方案（CPU-Z/ZenTimings 为 GPL/闭源）。
- BatteryHealth（调研候选之一）未收录：与内置 `mon_battery_report` 能力重叠，AD-0007 原则下不引入。
