# ⑬ 屏幕工具插件（only-u-screen）

## 1. 概述

功能域：**屏幕/显示器工具**。内置坏点检测脚本（全屏纯色循环）+ 调度宽松协议的第三方屏幕工具（坏点检测 GUI、DDC/CI 亮度调节、色温调节）。对标图吧工具箱「屏幕工具」分类。

- 包名：`only-u-screen`
- 开发状态：**已实现**（内置坏点检测可直接用；调度框架完成，工具收录待实测）
- 插件形态：标准 dsh.bundle 包，注册工具 `screen_tool_list` / `screen_tool_run` / `screen_deadpixel`

## 2. 构成

```
plugins\only-u-screen\
  package.json  cordis.patch.yml  index.js
  lib\
    catalog.js   runner.js   exitcodes.js   # 调度框架（各带副本，包自足）
    runScript.js                            # 内置脚本执行器
  assets\
    deadpixel.ps1     # 坏点检测：所有屏幕全屏循环纯色（WinForms，只读显示）
  knowledge\

    candidates.screen.json  # 候选：DefectPX / Twinkle Tray / Monitorian / Lightbulb / go-sct（待实测）
    README.md
  tools\                    # 工具二进制随包分发（当前为空）
```

## 3. 应用场景

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 坏点检测 | 验机、屏幕出现斑点 | screen_deadpixel 全屏纯色循环，用户肉眼检查 |
| B 亮度调节 | 外接显示器太亮/太暗 | screen_tool_run（Twinkle Tray/Monitorian，DDC/CI） |
| C 色温/护眼 | 晚上刺眼 | screen_tool_run（go-sct CLI / Lightbulb） |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「坏点检测」**
> 帮我检测屏幕坏点。启动全屏纯色循环，告诉我在哪个颜色下检查什么，结束后我会汇报结果。

**场景 B「亮度调节」**
> 外接显示器太亮了，帮我看看有没有能调亮度的工具，先说明用什么方式调（DDC/CI 或系统设置）。

**场景 C「色温」**
> 晚上屏幕太刺眼，帮我用命令行把色温调暖（比如 3500K），说明效果与如何恢复。

## 5. 使用方法

1. 坏点检测：直接调 `screen_deadpixel`（只读显示，用户按 Esc/点击结束，无需确认门）。
2. 亮度/色温 → `screen_tool_list` → `screen_tool_run({ tool, params })`；GUI 工具（Twinkle Tray 等）由用户自行操作。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-screen
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-screen`。

## 7. 开发要点

### 7.1 已实现

- **内置 `screen_deadpixel`（可用）**：WinForms 全屏纯色循环（红/绿/蓝/白/黑/黄/青/品红，1.5s 切换），覆盖所有显示器，Esc 或点击结束。只读显示、无写操作；无桌面会话时返回引导提示。
- **调度框架**：与 03 同构副本，`screen_` 前缀。候选全部 `green`（显示/亮度类，无写盘风险）。
- 配置与超时：`pollTimeoutMs: 10000`；`screen_tool_run` 工具级 `timeoutMs: 1800000`（上限，单工具实际超时取条目 `timeoutMs`，当前候选 60000/600000）。
- ✅ 接线冒烟通过（内置坏点检测注册成功、空库→空目录、候选不可调度；测试脚本 `temp\smoke-test-wiring.mjs`，2026-08-23）。
