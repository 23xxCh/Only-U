# ① 诊断插件（only-u-diagnose）

## 1. 概述

功能域：**系统诊断**。只读检查一台 Windows 电脑的健康状态：磁盘空间、内存压力、TOP 进程、启动项、临时目录、近期关键事件、打印机、PnP 驱动异常、SMART 健康，输出「结论 + 证据 + 红灯区」。

- 包名：`only-u-diagnose`
- 开发状态：**已实现**（`portable\diagnose.ps1` 离线地板 + Cordis 打包完成，见 `插件文档\插件\only-u-diagnose\`；第三方 MIT 诊断工具已拆为独立插件 03）
- 插件形态：标准 dsh.bundle 包，装进 deepseek-harness / dsh-TUI 后注册工具 `ops_diagnose`

## 2. 构成

```
plugins\only-u-diagnose\
  package.json                  # dsh.bundle manifest
  cordis.patch.yml              # insert 行注册插件
  index.js                      # apply(ctx, config)：注册 ops_diagnose
  assets\
    diagnose.ps1                # 诊断脚本（从 portable\diagnose.ps1 原样拷入，随包分发）
  lib\
    runScript.js                # powershell 执行辅助（② 清理插件共用同一模式）
    parse.js                    # 红灯区输出解析（可独立单测）
```

> 第三方 MIT 诊断工具调度已拆为独立插件 [03-插件-诊断工具调度.md](03-插件-诊断工具调度.md)，本插件只管内置 PowerShell 诊断。离线入口 `diagnose.cmd` 在仓库 `portable\`（08 烤盘分发），**不随插件包分发**。

脚本能力清单（`diagnose.ps1` 已实现的 11 个采集段）：磁盘、内存、提交内存、页面文件、TOP5 进程、启动项数、临时目录回收候选、近 7 天关键事件、打印机、PnP 驱动异常、SMART。红灯区输出格式：`=== 报告红灯区 ===` 段内每行 `! {flag}`。

## 3. 应用场景（什么时候用得上）

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 日常体检 | 用户不确定电脑有没有毛病 | 全面只读检查，按严重程度排序出结论 |
| B 电脑卡顿排查 | 开机慢 / 运行卡 | 内存占用、启动项、磁盘健康、近期错误的联合诊断 |
| C C 盘空间分析 | C 盘告急，想知道被什么占满 | 磁盘使用率 + 可回收临时目录大小 + 占用分析 |
| D 蓝屏事后取证 | 刚蓝屏重启，想查原因 | 近 7 天关键事件 + 存储错误事件，只报事实 |
| E 二手电脑验机 | 收货后验机 | 硬件体检报告（SMART/内存/驱动异常/近期错误） |
| F 无网离线诊断 | 没网 / 模型不可达 | 直接跑 `diagnose.cmd`，不经过 AI |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「日常体检」**
> 给我的电脑做一次全面体检，重点看磁盘空间、内存压力和近期系统错误。只做只读检查，按严重程度排序给我结论和建议，数字带单位。

**场景 B「电脑卡顿排查」**
> 电脑最近很卡，帮我诊断：内存占用情况、启动项数量、磁盘健康状态、近期系统错误。只做只读检查，给出根因结论，不要动任何东西。

**场景 C「C 盘空间分析」**
> 我的 C 盘只剩不到 15% 空间了，先只读诊断：磁盘整体使用率、可回收的临时目录大小、TOP 占内存进程。告诉我哪些能安全处理，哪些需要我手动决定。

**场景 D「蓝屏事后取证」**
> 电脑刚才蓝屏重启了，帮我查近 7 天的关键系统事件和存储错误事件。只报事实和证据（时间、来源、事件 ID），不要下「必须重装系统」的结论。

**场景 E「二手电脑验机」**
> 我刚收到一台二手笔记本，帮我做硬件体检：磁盘 SMART 健康状态、内存容量、驱动异常设备列表、近期系统错误。输出一份验机报告，结论先行。

**场景 F「无网离线诊断」**
> （没网时不用 AI——直接双击 `portable\diagnose.cmd`，诊断报告本地输出）

## 5. 使用方法

- **TUI 路径（有网）**：装好插件后启动 `dsh --profile dsh-tui`，直接粘贴第 4 节的提示词，模型会调用 `ops_diagnose` 并组织成报告。
- **离线路径（无网）**：双击 `portable\diagnose.cmd`（或盘根 `诊断.cmd`），60 秒内出全量报告，红灯区置顶。
- 两条路径跑的是**同一份脚本**，报告口径一致。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-diagnose
pnpm dsh --profile dsh-tui --dump-config     :: 出现 "# == only-u-diagnose" 层即成功
pnpm dsh --profile dsh-tui                    :: 真机对话触发 ops_diagnose
```

纯 harness（无 TUI）：`dsh plugin --profile ops add ..\plugins\only-u-diagnose`。

`plugins\only-u-diagnose\lib\runScript.js`：

```js
import { spawn } from 'node:child_process'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const pkgDir = dirname(fileURLToPath(import.meta.url))

/**
 * 用 powershell.exe 跑包内 ps1 脚本，返回结构化结果。
 * - UTF-8 解码输出（脚本内已设 [Console]::OutputEncoding = UTF8）
 * - timeoutMs 超时或 signal 中止 → taskkill /T /F 杀整棵进程树
 * - 全默认值、不抛异常：任何失败都作为结构化结果返回，绝不拖垮 agent-loop
 */
export async function runScript(relPath, args, timeoutMs, signal) {
  const ps1 = join(pkgDir, '..', 'assets', relPath)
  const result = { exitCode: null, stdout: '', stderr: '', timedOut: false, aborted: false }

  let settled = false
  const killTree = (proc) => {
    if (proc.pid) spawn('taskkill', ['/PID', String(proc.pid), '/T', '/F'], { stdio: 'ignore' })
  }

  return new Promise((resolve) => {
    const proc = spawn('powershell.exe', [
      '-NoProfile', '-NonInteractive', '-ExecutionPolicy', 'Bypass',
      '-File', ps1, ...args,
    ], { windowsHide: true })

    const timer = timeoutMs > 0 ? setTimeout(() => {
      result.timedOut = true
      killTree(proc)
      finish()
    }, timeoutMs) : null

    const onAbort = () => {
      result.aborted = true
      killTree(proc)
      finish()
    }
    signal?.addEventListener('abort', onAbort, { once: true })

    const finish = () => {
      if (settled) return
      settled = true
      if (timer) clearTimeout(timer)
      signal?.removeEventListener('abort', onAbort)
      resolve(result)
    }

    proc.stdout.setEncoding('utf8')
    proc.stderr.setEncoding('utf8')
    proc.stdout.on('data', (d) => { result.stdout += d })
    proc.stderr.on('data', (d) => { result.stderr += d })
    proc.on('error', (err) => { result.stderr += String(err); finish() })
    proc.on('close', (code) => { result.exitCode = code; finish() })
  })
}
```

`plugins\only-u-diagnose\index.js`（解析函数独立在 `lib\parse.js`，便于单测；已实现，见 `插件文档\插件\only-u-diagnose\`）：

```js
import { runScript } from './lib/runScript.js'
import { parseRedFlags } from './lib/parse.js'

export const name = 'only-u-diagnose'

export function apply(ctx, config = {}) {
  const timeoutMs = config.diagnoseTimeoutMs ?? 240000

  ctx.tools.register({
    name: 'ops_diagnose',
    description: '对当前 Windows 电脑做一次只读系统诊断：磁盘空间、内存压力、'
      + 'TOP5 占内存进程、启动项数量、临时目录、近 7 天关键系统事件、打印机、'
      + 'PnP 驱动异常、SMART 健康。只读，不修改任何东西；无网络时也可用。'
      + '返回完整报告文本与红灯区列表，模型负责把它整理成用户能看懂的中文结论。',
    parameters: {},
    output: {
      schema: {
        type: 'object',
        additionalProperties: false,
        required: ['kind', 'exitCode', 'timedOut', 'aborted', 'stdout', 'stderr', 'redFlags'],
        properties: {
          kind: { type: 'string', const: 'diagnose' },
          exitCode: { type: ['integer', 'null'] },
          timedOut: { type: 'boolean' },
          aborted: { type: 'boolean' },
          stdout: { type: 'string' },
          stderr: { type: 'string' },
          redFlags: { type: 'array', items: { type: 'string' } },
        },
      },
      render: (_args, value) => {
        const head = value.redFlags.length > 0
          ? `【红灯区 ${value.redFlags.length} 项】${value.redFlags.join('；')}\n\n`
          : ''
        const tail = value.timedOut ? '\n\n[诊断超时，部分项目未完成]' : (value.aborted ? '\n\n[诊断被中止]' : '')
        return [{ type: 'text', text: head + value.stdout + tail }]
      },
    },
    timeoutMs,
    async execute(_args, exec) {
      const r = await runScript('diagnose.ps1', [], timeoutMs, exec.signal)
      return { kind: 'diagnose', redFlags: parseRedFlags(r.stdout), ...r }
    },
  })
}
```
