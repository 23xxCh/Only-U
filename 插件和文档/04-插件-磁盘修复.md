# ④ 磁盘修复插件（only-u-disk-repair）

## 1. 概述

功能域：**磁盘检测/修复**。调度 MIT 协议的磁盘修复类工具（坏道检测、扇区刷新）。**写盘操作执行前必须经用户确认。**

- 包名：`only-u-disk-repair`
- 开发状态：**已实现**（调度框架代码完成，见 `插件文档\插件\only-u-disk-repair\`；工具收录待实测，实测前知识库为空 = 不可调度）
- 插件形态：标准 dsh.bundle 包，注册工具 `disk_tool_list` / `disk_tool_run`

## 2. 构成

```
plugins\only-u-disk-repair\
  package.json  cordis.patch.yml  index.js
  lib\
    catalog.js   runner.js   exitcodes.js   # 调度框架（与 03/05 各带副本，包自足）
  knowledge\
    disk-repair-tools.json       # 生效知识库（空 = fail-closed）
    candidates.disk-repair.json  # 候选：AmazeHealDisk（待实测）
    README.md
  tools\                          # MIT 工具二进制随包分发（当前为空）
```

## 3. 应用场景

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 怀疑硬盘坏道 | 读写异常、异响排除后仍怀疑 | 列出磁盘检测工具与风险说明，先做只读坏道扫描 |
| B 深度磁盘检查 | SMART 摘要（01 内置）显示可疑 | 补充坏道级扫描 |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「怀疑硬盘坏道」**
> 我怀疑硬盘有坏道，帮我列出可用的磁盘检测工具并说明每个的风险。先选一个做只读坏道扫描，扫描前先向我确认要跑什么命令。

**场景 B「深度磁盘检查」**
> 内置诊断的 SMART 健康状态可疑，帮我用磁盘工具做一次深度检查，任何写盘操作执行前都要先给我说明影响。

## 5. 使用方法

1. 用户描述故障 → `disk_tool_list` 列工具（含风险）→ `disk_tool_run({ tool, params })`。
2. 写盘/修复类条目弹确认条（工具名 + 参数 + 风险）→ 用户允许才执行 → 结构化结果整理成结论。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-disk-repair
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-disk-repair`。

## 7. 开发要点

### 7.1 已实现（调度框架）

- 与 03 同构的框架副本，工具名加 `disk_` 前缀避免跨插件冲突。
- 收录条目 `tier: red`（扇区刷新是写盘操作）→ `disk_tool_run` 执行前 `approval.request` 确认，拒绝返回结构化 `tool-denied`；无审批服务 fail-closed。
- exe 一律从包内 `tools\` 解析（工具随包分发）。
- 配置与超时：`cordis.patch.yml` 配置键 `pollTimeoutMs: 10000`（结果文件轮询等待上限）；`disk_tool_run` 工具级 `timeoutMs: 1800000`（上限，单工具实际超时取知识库条目 `timeoutMs`，当前候选 900000）。知识库条目字段：`argTemplate`（参数模板，仅 `${key}` 填充）、`outPattern`（结果文件路径模板）、`exitCodes`（退出码→含义）、`maxOutBytes: 524288`（输出截断上限）。
- ✅ 接线冒烟通过（空库→空目录、未知工具抛错、fillTemplate 注入安全、候选 `verified:false` 不可调度；测试脚本 `temp\smoke-test-wiring.mjs`，2026-08-23）。
