# Only-U 插件设计（总设计）

## 1. 文档目的与读者

本套文档是 Only-U 项目的**插件开发文档集**：一份总设计（本文件）+ 每个插件一份独立文档。

读者：
- 项目成员（人）：快速了解有哪些插件、各自干什么、怎么装怎么用。
- 负责开发的 AI agent：每份分册自足到「读完就能照着开发」，代码已落地在 `插件文档\插件\`。

原则（队长定的组织规则）：
- **一个功能 = 一个插件 = 一份 md**。
- 同一插件内可以使用多个 MIT 协议软件（按功能归并，不按软件拆插件）。
- 插件之间功能不重复。
- 所有插件都是**标准 DSH 插件**（dsh.bundle 格式），能直接 `dsh plugin add` 装进 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) / [dsh-TUI](https://github.com/ccch1mneyyy/dsh-TUI)，脚本、skill、第三方工具全部作为包内资源随插件分发。
- **只收宽松协议第三方工具：MIT / BSD-2-Clause / BSD-3-Clause / Apache-2.0 / Unlicense / zlib。GPL、MPL 等传染性协议一律不碰**（项目计划商业化）。

```

├─────────────────────────────────────────────────────┤
│  deepseek-harness（dsh 内核）—— "Everything is a Plugin" │
│   · Cordis 插件树：01-06、09-15 都以 dsh.bundle 包挂载      │
├───────────────┬─────────────────────────────────────┤
│ Skill 层（06）  │ Cordis 工具层（各功能插件注册的工具）         │
│ 场景调度/流程纪律 │ ops_diagnose / ops_clean /               │
│               │ diag_tool_* / disk_tool_* / sys_tool_*     │
│               │ dbench_tool_* / mon_tool_* / stress_tool_* │
│               │ net_tool_* / screen_tool_* / peri_tool_*   │
│               │ maint_tool_* / 内置脚本工具 9 个             │
├───────────────┴─────────────────────────────────────┤
│ 包内资源：diagnose.ps1 / clean.ps1 / SKILL.md /           │

└─────────────────────────────────────────────────────┘
```

一条完整调用链（用户说「C 盘满了帮我看看」）：

```
用户 → dsh-TUI 输入框 → deepseek-harness agent-loop
     → 06 skill 规则命中（先诊断后清理预览）
     → 调用 01 ops_diagnose 工具 → powershell.exe 跑包内 assets\diagnose.ps1 → 结构化结果回给模型
     → 模型组织「结论+证据+建议」→ 调用 02 ops_clean 工具（execute=false）→ 预览清单回给模型
     → 用户说「确认执行」→ 02 ops_clean(execute=true) → dsh-TUI 弹确认条 → 用户允许
     → powershell 跑 clean.ps1 -Execute → 日志落盘 → 结果回给用户
```

第三方工具调用链（「怀疑硬盘坏了」）：06 skill 路由 → 04 `disk_tool_list` 列工具 → `disk_tool_run` → 确认条 → runner 执行包内工具 → 退出码/报告结构化返回。

08 打包插件负责把「装好 01–15 全部插件的 profile + 便携 Node + dsh 内核」整体烤进 U 盘，客户机零安装双击即用。

## 4. Cordis 插件开发规范（所有插件共用）

### 4.1 组合包三件套

每个插件包 = 一个目录，三个文件起：

```
plugins\<包名>\
├── package.json       # 声明 dsh.bundle
├── cordis.patch.yml   # 注册插件行
└── index.js           # 插件入口（export const name + export function apply）
```

`package.json` 模板：

```json
{
  "name": "only-u-diagnose",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml", "assets", "lib"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

要点：
- **零 npm 依赖**：只用 Node 内置模块（`node:child_process` / `node:path` / `node:fs`），绕开 profile 里 node_modules 隔离的传递依赖坑，也保证烤盘体积可控。
- `files` 必须包含所有运行时资源（脚本、SKILL.md、MIT 工具二进制），随包分发。

`cordis.patch.yml` 模板（insert 一行注册插件）：

```yaml
- insert:
    - id: only-u-diagnose
      name: only-u-diagnose
      config:
        diagnoseTimeoutMs: 240000
```

`index.js` 骨架：

```js
export const name = 'only-u-diagnose'

// 硬性要求（2026-08-23 实测）：凡直接用 ctx.tools / ctx.skills，必须声明对应
// inject，缺了启动直接失败（'cannot get property "tools" without inject'）。
// ctx.get(x) 软探针不需要声明。
export const inject = ['tools']

export function apply(ctx, config = {}) {
  // 所有 config 键都要 ?? 兜底，插件加载失败绝不能拖垮 dsh 启动
  // ctx.tools.register({ ... }) —— 见 4.2
}
```

### 4.2 工具注册

```js
ctx.tools.register({
  name: 'ops_diagnose',          // 模型可见的工具名（下划线风格）
  description: '...',            // 写给模型看的：什么情况用、只读还是写、有什么限制
  parameters: {                  // 参数 map 形式（与官方 tool-bash 一致）
    foo: { type: 'string', required: true, description: '...' },
  },
  output: {
    schema: { /* JSON Schema，约束 execute 的返回值 */ },
    render: (_args, value) => [{ type: 'text', text: '...' }],  // 给模型看的文本投影
  },
  timeoutMs: 240000,             // 协作超时预算，执行器按它杀进程
  async execute(args, exec) {
    // 只返回 output.schema 约束的 JSON 值
    // exec = { agent, callId, signal }，长任务要观察 exec.signal
  },
})
```

权威样例：`dsh\packages\shell\tool-bash\src\index.ts`（官方 bash 工具注册）；接口定义：`dsh\packages\core\tools\src\index.ts`（`ToolDefinition`）。

### 4.3 删除/高危操作确认机制

DSH 有现成的审批服务：工具执行路径内请求审批，dsh-TUI 会弹确认条（工具名 + 理由 + Yes/No，Esc/Ctrl+C = 拒绝）。

```js
const approval = ctx.get('approval')          // 获取审批服务
if (!approval) {
  return { kind: 'clean-denied', outcome: 'unavailable' }   // 没有审批服务 = fail-closed
}
const outcome = await approval.request({
  agent: exec.agent,
  toolName: 'ops_clean',
  callId: exec.callId,
  reason: '清理预览：约 X（白名单 5 类）。是否执行删除？',
  signal: exec.signal,
})
// outcome ∈ 'allowed-once' | 'rejected' | 'cancelled' | 'unavailable'
// 仅 'allowed-once' 才执行，其余一律拒绝并结构化返回给模型
```

权威源码：`dsh\packages\interaction\user-approval\src\index.ts`。**02 的 `-Execute` 和 04/05 的写盘类工具都走这个机制**，这是「确认才执行」的运行时保证，不靠模型自觉。

### 4.5 包内资源寻址

脚本/SKILL.md/二进制都随包分发，运行时**不依赖仓库相对路径**：

```js
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const pkgDir = dirname(fileURLToPath(import.meta.url))       // 包根
const diagnosePs1 = join(pkgDir, 'assets', 'diagnose.ps1')   // 包内脚本
```

### 4.6 工具名前缀约定（避免跨插件冲突）

dsh 的工具注册表全局唯一。命名规则：
- 内置工具用 `ops_` 前缀（`ops_diagnose`/`ops_clean`）。
- 第三方调度工具按域加前缀：`diag_tool_*`（03）、`disk_tool_*`（04）、`sys_tool_*`（05）、`dbench_tool_*`（09）、`mon_tool_*`（10）、`stress_tool_*`（11）、`net_tool_*`（12）、`screen_tool_*`（13）、`peri_tool_*`（14）、`maint_tool_*`（15）。
- 内置 PowerShell 脚本工具用域前缀、无 `_tool_` 中缀：`mon_battery_report`/`mon_nvidia_smi`（10）、`stress_winsat`（11）、`net_wifi_scan`/`net_port_check`（12）、`screen_deadpixel`（13）、`peri_usb_verify`（14）、`maint_driver_clean`/`maint_dx_repair`（15）。

### 4.7 烤盘注意（FAT32 限制）

`plugin add ..\plugins\<x>` 本地路径安装会生成 `link:` 依赖（profile 的 node_modules 里是 junction），robocopy/FAT32 存不了 junction。两条路：
- 推荐：bake 步骤 4 之后，对 `plugins\<x>` 做**实体目录 robocopy** 覆盖 `$profDst\node_modules\<x>`；
- 或：`pnpm pack` 打成 tgz 再 `plugin add .\xxx.tgz`（真实文件安装，无 junction）。

### 4.8 2026-08-23 增补：实测修正与新增铁律

当日 13 个插件包全量实装验证（PR #41）换来的修正，全部已实测坐实：

**组合与加载**
1. **inject 声明是硬性要求**：直接使用 `ctx.tools` 的包缺 `export const inject = ['tools']` → 启动失败（13/13 全中，已修）。`ctx.skills` 同理声明 `['skills']`。
2. **`output.schema` 的 `type` 只能单类型字符串**：`type: ['integer','null']` 被 dsh 校验器拒绝（`unsupported JSON schema`）。可空语义用业务字段表达，不写类型数组。
3. **`- insert:` 插入的条目会被正常 apply**（此前有说法称孤儿条目不激活，实测证伪）；裸 `- id:` 是改写已有行的语义，匹配不到目标会被静默跳过——新增行永远走 insert。
4. **挂进 dsh-tui 应用行 inject 链的插件**（如 only-u-bundle）必须默认导出 `Service` 子类提供同名服务，否则启动时永远 pending。
5. 插件包规范位置：`plugins\`（2026-08-23 自 `插件和文档\插件\` 迁入，文档 08 安装命令即指向此处）。

**权威范本**（照抄起步）
- `plugins\only-u-clean\` —— 工具 + 审批门 + .ps1 资产的标准形态（含 inject 声明）
- `plugins\only-u-bundle\` —— Service 子类 + 斜杠命令 + tuiDialogs/tuiStatus/tuiScenes 的壳集成形态

**新增铁律**
6. **写盘类工具禁止自动选择目标盘**：盘符参数必填（usb-verify 教训——自动选第一个可移动盘可能把测试文件写进 Only-U 启动盘自身）。
7. **AI 工具会话历史视同用户文档**：与 Desktop/Documents/Downloads/Pictures 同级误删保护。实测依据：38.7GB 会话文件经盘点全为用户 AI 项目工作记录（2026-08-23，险被当垃圾清掉）。对这类数据默认动作是「迁移（junction）」而非「删除」。
8. **license 口径为宽松集**（MIT/BSD/Apache-2.0/Unlicense/zlib，允许商业重分发），不是仅 MIT；GUI-only 工具（无 headless CLI）违反 ADR-0007 第 3 条，候选表加 `rejected` 标记留痕。

规则：
- **每个收录工具必须逐条留档三条准入**：① 能力不可达（PowerShell 做不到）；② 授权干净（宽松协议，允许商业重分发）；③ 有机器可读接口（CLI 静默参数/报告导出/退出码可解析）。未过审 = 不可调度（fail-closed）。
- 宽松协议分发义务：**保留版权声明**——每个工具目录随附其 LICENSE 文件（无 LICENSE 文件的仓库如 CrystalDiskInfo/CrystalDiskMark，收录时下载留存官方许可页证据）。
- 知识库条目里带 `audit` 字段记录留档证据。
