# ② 清理插件（only-u-clean）

## 1. 概述

功能域：**安全清理**。只删白名单里的东西：TEMP 临时文件、缩略图缓存、WER 错误报告、Windows Update 下载缓存、回收站。**默认只预览，用户确认后才执行**；桌面/文档/下载/图片永不清理（误删防护）。

- 包名：`only-u-clean`
- 开发状态：**已实现**（`portable\clean.ps1` 离线地板 + Cordis 打包完成，见 `插件文档\插件\only-u-clean\`）
- 插件形态：标准 dsh.bundle 包，注册工具 `ops_clean`（预览 + 确认后执行）

## 2. 构成

```
plugins\only-u-clean\
  package.json                  # dsh.bundle manifest
  cordis.patch.yml              # insert 行注册插件
  index.js                      # apply(ctx, config)：注册 ops_clean
  assets\
    clean.ps1                   # 清理脚本（从 portable\clean.ps1 原样拷入，随包分发）
  lib\
    runScript.js                # 与 ① 诊断插件同一模式的 powershell 执行辅助
    parse.js                    # blocked 清单/预览摘要解析（可独立单测）
```

脚本已有能力（`clean.ps1`）：
- 5 类白名单：TEMP（4 个临时目录，7 天年龄门）、缩略图缓存（thumbcache_*.db）、WER 报告、Windows Update 下载缓存、回收站。
- 保护根：桌面/文档/下载/图片（前缀判定 `Test-Protected`），命中即跳过并输出 `blocked (delete-protection): <路径>`。
- 默认预览；`-Execute` 才真实删除；执行后日志写 `$PSScriptRoot\logs\clean-<时间戳>.log`（随包运行 = 包内 `assets\logs\`），stdout 输出 `log: <路径>` 行，由 index.js 解析回传 `logPath`。
- 注意：脚本输出文案仍写「执行后日志将写入 portable\logs\」，是历史文案（脚本侧待修），实际落盘位置以 `log:` 行回传的路径为准。

## 3. 应用场景（什么时候用得上）

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A C 盘告急腾空间 | C 盘空间不足 | 预览一遍可回收内容（大小+路径清单），等确认 |
| B 只想看不动手 | 想知道有多少垃圾但不放心删 | 纯预览，零副作用 |
| C 确认清理 | 用户看过预览说「确认，执行」 | 弹确认条 → 执行 → 出日志 |
| D 误删担忧 | 用户怕删错文件 | 展示保护清单（永不碰什么）+ 完整路径清单 |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「C 盘告急腾空间」**
> C 盘空间不足了，帮我预览一遍能安全清理的内容（临时文件、缓存、更新残留），列出可回收大小和具体路径，等我确认再执行。

**场景 B「只想看不动手」**
> 帮我看看这台电脑有多少可回收垃圾，只做预览，不要执行任何删除。

**场景 C「确认清理」**
> 按刚才的预览清单执行清理，跳过被保护的路径，执行前把将删除的路径清单再给我看一遍。

**场景 D「误删担忧」**
> 清理前先告诉我你永远不会碰哪些目录（桌面、文档、下载、图片），并给出这次清理的完整路径清单，我确认之前什么都不要删。

## 5. 使用方法

- **TUI 路径**：粘贴第 4 节提示词 → 模型先调 `ops_clean(execute=false)` 出预览 → 用户确认 → 模型调 `ops_clean(execute=true)` → **dsh-TUI 弹出确认条**（显示工具名 + 清理摘要理由）→ 用户允许才真正执行。
- **离线路径**：双击 `portable\clean.cmd` 看预览；`portable\clean.cmd -Execute` 才执行。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-clean
pnpm dsh --profile dsh-tui --dump-config     :: 出现 "# == only-u-clean" 层即成功
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-clean`。

## 7. 开发要点（打包接线）

### 7.1 三件套代码草案

`package.json` / `cordis.patch.yml` / `lib\runScript.js` 与 ① 诊断插件同构（见 [01-插件-诊断.md](01-插件-诊断.md) 7.1，把包名换成 `only-u-clean`、config 键换成 `cleanPreviewTimeoutMs: 240000` / `cleanExecuteTimeoutMs: 600000`）。

`plugins\only-u-clean\index.js`（核心：预览 → 审批 → 条件执行；解析函数独立在 `lib\parse.js`，已实现，见 `插件文档\插件\only-u-clean\`）：

```js
import { runScript } from './lib/runScript.js'
import { parseBlocked, summarizePreview } from './lib/parse.js'

export const name = 'only-u-clean'

export function apply(ctx, config = {}) {
  const previewTimeoutMs = config.cleanPreviewTimeoutMs ?? 240000
  const executeTimeoutMs = config.cleanExecuteTimeoutMs ?? 600000

  ctx.tools.register({
    name: 'ops_clean',
    description: '清理 Windows 垃圾文件。execute=false 只预览（只读，返回可回收大小与路径清单）；'
      + 'execute=true 真实删除，执行前会向用户弹出确认，未获允许绝不执行。'
      + '只清理白名单：TEMP 临时文件、缩略图缓存、WER 错误报告、Windows Update 下载缓存、回收站。'
      + '桌面/文档/下载/图片永不清理。',
    parameters: {
      execute: {
        type: 'boolean',
        required: false,
        description: 'false=预览（只读，默认）。true=按预览清单真实删除；'
          + '会弹出用户确认，用户拒绝则返回 denied 而不是执行。',
      },
    },
    output: {
      schema: {
        oneOf: [
          {
            type: 'object',
            additionalProperties: false,
            required: ['kind', 'exitCode', 'timedOut', 'aborted', 'stdout', 'stderr', 'blocked'],
            properties: {
              kind: { type: 'string', const: 'clean-preview' },
              exitCode: { type: ['integer', 'null'] },
              timedOut: { type: 'boolean' },
              aborted: { type: 'boolean' },
              stdout: { type: 'string' },
              stderr: { type: 'string' },
              blocked: { type: 'array', items: { type: 'string' } },
            },
          },
          {
            type: 'object',
            additionalProperties: false,
            required: ['kind', 'exitCode', 'timedOut', 'aborted', 'stdout', 'stderr', 'logPath'],
            properties: {
              kind: { type: 'string', const: 'clean-executed' },
              exitCode: { type: ['integer', 'null'] },
              timedOut: { type: 'boolean' },
              aborted: { type: 'boolean' },
              stdout: { type: 'string' },
              stderr: { type: 'string' },
              logPath: { type: ['string', 'null'] },
            },
          },
          {
            type: 'object',
            additionalProperties: false,
            required: ['kind', 'outcome'],
            properties: {
              kind: { type: 'string', const: 'clean-denied' },
              outcome: { type: 'string', enum: ['rejected', 'cancelled', 'unavailable'] },
              message: { type: 'string' },
            },
          },
        ],
      },
      render: (_args, value) => {
        if (value.kind === 'clean-denied') {
          return [{ type: 'text', text: `[清理未执行：用户未批准（${value.outcome}）] ${value.message ?? ''}` }]
        }
        if (value.kind === 'clean-preview') {
          const guard = value.blocked.length > 0
            ? `\n\n被保护跳过（永不清理）：${value.blocked.join('；')}` : ''
          return [{ type: 'text', text: `[清理预览（只读，未删除任何文件）]\n${value.stdout}${guard}` }]
        }
        return [{ type: 'text', text: `[清理已执行] 日志：${value.logPath}\n${value.stdout}` }]
      },
    },
    timeoutMs: executeTimeoutMs,
    async execute(args, exec) {
      const doExecute = args.execute === true

      // 1. 无论预览还是执行，都先跑一次全新预览（不信任模型转述）
      const preview = await runScript('clean.ps1', [], previewTimeoutMs, exec.signal)
      if (preview.timedOut || preview.aborted) {
        return { kind: 'clean-preview', blocked: parseBlocked(preview.stdout), ...preview }
      }

      // 2. 只预览：直接返回
      if (!doExecute) {
        return { kind: 'clean-preview', blocked: parseBlocked(preview.stdout), ...preview }
      }

      // 3. 执行前必须过审批服务（dsh-TUI 会弹确认条）
      const approval = ctx.get('approval')
      if (!approval) {
        return { kind: 'clean-denied', outcome: 'unavailable', message: '当前环境没有审批服务，无法确认删除' }
      }
      const outcome = await approval.request({
        agent: exec.agent,
        toolName: 'ops_clean',
        callId: exec.callId,
        reason: `清理执行确认：${summarizePreview(preview.stdout)}（白名单：TEMP/缩略图缓存/WER/更新缓存/回收站）。`
          + '桌面、文档、下载、图片永不清理。允许本次删除？',
        signal: exec.signal,
      })

      // 4. 仅 allowed-once 才执行，其余一律拒绝（fail-closed）
      if (outcome !== 'allowed-once') {
        return { kind: 'clean-denied', outcome, message: '用户未批准清理执行' }
      }

      const r = await runScript('clean.ps1', ['-Execute'], executeTimeoutMs, exec.signal)
      const logPath = r.stdout.match(/log:\s*(.+\.log)/)?.[1] ?? null
      return { kind: 'clean-executed', logPath, ...r }
    },
  })
}
```

### 7.2 关键设计说明

- **参数面最小化 = 安全面最小化**：`ops_clean` 只有一个布尔开关，白名单/年龄门/保护根全部锁死在脚本里，模型没有任何额外自由度。
- **执行前重跑预览**：不信任模型此前看到的内容，审批理由永远来自刚刚那次全新预览。
- **fail-closed**：审批服务缺失（如纯 headless 环境）→ 直接 `clean-denied(unavailable)`，绝不默默执行。
- 已知残余风险：模型仍可用通用 `pwsh` 工具绕过 `ops_clean` 直接跑脚本——靠 ⑥ skill 纪律约束，后续可用 toolFilter 收窄通用 shell 工具（见 06 文档开发任务）。
