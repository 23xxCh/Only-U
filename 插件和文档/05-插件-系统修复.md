# ⑤ 系统修复插件（only-u-system-repair）

## 1. 概述

功能域：**系统镜像修复**。调度 MIT 协议的系统修复类工具（系统镜像修复、损坏文件验证）。**系统级写操作执行前必须经用户确认。**

- 包名：`only-u-system-repair`
- 开发状态：**已实现**（调度框架代码完成，见 `插件文档\插件\only-u-system-repair\`；工具收录待实测，实测前知识库为空 = 不可调度）
- 插件形态：标准 dsh.bundle 包，注册工具 `sys_tool_list` / `sys_tool_run`

## 2. 构成

```
plugins\only-u-system-repair\
  package.json  cordis.patch.yml  index.js
  lib\
    catalog.js   runner.js   exitcodes.js   # 调度框架（与 03/04 各带副本，包自足）
  knowledge\
    system-repair-tools.json       # 生效知识库（空 = fail-closed）
    candidates.system-repair.json  # 候选：WindowsMedicator（待实测）
    README.md
  tools\                           # MIT 工具二进制随包分发（当前为空）
```

## 3. 应用场景

| 场景 | 触发条件 | 本插件做什么 |
|------|----------|--------------|
| A 系统文件损坏 | SFC/DISM 初步检查后仍异常 | 列出修复工具与作用，执行前逐项确认 |
| B 修复前评估 | 问题严重，不敢乱动 | 只做检测和评估，任何修复操作先说明影响等确认 |

## 4. 场景提示词（直接复制进 TUI 使用）

**场景 A「系统文件损坏」**
> 系统镜像文件可能损坏，帮我列出可用的修复工具和它的作用。任何修复动作执行前必须向我确认，先说明会影响什么。

**场景 B「修复前评估」**
> 这台电脑问题比较严重，先只做检测和评估，不要执行任何修复。任何系统级写操作都要先给我说明影响范围，等我确认。

## 5. 使用方法

1. 用户描述故障 → `sys_tool_list` 列工具（含风险）→ `sys_tool_run({ tool, params })`。
2. 系统级写操作弹确认条（工具名 + 参数 + 风险）→ 用户允许才执行 → 结构化结果整理成结论。

## 6. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-system-repair
```

纯 harness：`dsh plugin --profile ops add ..\plugins\only-u-system-repair`。

## 7. 开发要点

### 7.1 已实现（调度框架）

- 与 03 同构的框架副本，工具名加 `sys_` 前缀避免跨插件冲突。
- 收录条目 `tier: red`（系统级写操作）→ `sys_tool_run` 执行前 `approval.request` 确认，拒绝返回结构化 `tool-denied`；无审批服务 fail-closed。
- exe 一律从包内 `tools\` 解析（工具随包分发）。
- 配置与超时：`cordis.patch.yml` 配置键 `pollTimeoutMs: 10000`（结果文件轮询等待上限）；`sys_tool_run` 工具级 `timeoutMs: 1800000`（上限，单工具实际超时取知识库条目 `timeoutMs`，当前候选 1800000）。知识库条目字段：`argTemplate`（参数模板，仅 `${key}` 填充）、`outPattern`（结果文件路径模板）、`exitCodes`（退出码→含义）、`maxOutBytes: 524288`（输出截断上限）。
- ✅ 接线冒烟通过（空库→空目录、未知工具抛错、fillTemplate 注入安全、候选 `verified:false` 不可调度；测试脚本 `temp\smoke-test-wiring.mjs`，2026-08-23）。
