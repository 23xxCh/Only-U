# ⑯ 卸载工具插件（only-u-uninstaller）

> 状态：**草稿（待队长评审）**。评估产出，由「geek 调研」结论驱动。
> 核心约束：**插件不依赖用户电脑是否装有 geek、是否装有任何软件、是否联网、是否预装 .NET 等运行时。** 一切能力随 Only-U 包分发，插入陌生电脑即可用。

## 1. 概述

功能域：**程序卸载**（对标 Geek Uninstaller / 图吧工具箱「卸载工具」类）。列举已装程序、静默卸载、残留清理。

- 包名：`only-u-uninstaller`（若并入现有域则候选名 `only-u-sys-maintain` 扩展，见 §10 归属决策）
- 插件形态：标准 dsh.bundle 包（与 01/02 插件同构），注册 5 个工具
- 协议边界：本插件内只收宽松协议资源（PowerShell 脚本自研 + BCUninstaller Apache-2.0）

### 1.1 为什么不依赖 geek（前置结论）

| 来源 | 结论 |
|------|------|
| 官方 Geek Uninstaller（geekuninstaller.com） | 闭源 freeware，未授权商业再分发 → 不能随 Only-U 分发 |
| gendloop/geek | Scoop 清单空壳，tag 里无 exe，安装器指向不存在的文件；GPL-2.0 → 排除 |
| MoatBursarWind/geek-uninstaller-tutorial | 盗版引流页 + 恶意分发模式（加密 payload）→ 永远不碰 |

**因此本插件与 geek 无任何代码、二进制、运行时依赖。** 功能由两层自有能力实现（§2）。

## 2. 零依赖架构（双层能力）

```
┌────────────────────────────────────────────────────────┐
│ A 层：内置 PowerShell（自研脚本随包分发，零 exe）           │
│   uni_list_installed 枚举 / uni_uninstall 卸载 /          │
│   uni_clean_residue 残留清理                              │
│   —— 永远可用，不依赖用户电脑上任何东西（系统自带的         │
│   powershell.exe + msiexec 不算额外依赖）                  │
├────────────────────────────────────────────────────────┤
│ B 层：BCUninstaller 调度（Apache-2.0，随包分发）            │
│   uni_tool_list / uni_tool_run                            │
│   —— 选 Portable 自包含变体：连 .NET 都不需要用户装          │
│   —— 收录未完成前 fail-closed，调度层不暴露可用工具          │
└────────────────────────────────────────────────────────┘
```

设计规则：

- **绝不**检测/查找/调用用户电脑上的 geek 或任何第三方卸载软件。
- **绝不**联网下载。U 盘插上即用，离线可用。
- **绝不**依赖用户预装运行时：B 层二进制必须选 self-contained 变体。
- B 层是 A 层的补充（PowerShell 够不着的深度残留扫描、批量无人值守、孤儿程序检测），A 层永远是兜底。

## 4. 工具注册设计（index.js 草案）

配置键（全部 ?? 兜底）：`uniListTimeoutMs: 120000`、`uniUninstallTimeoutMs: 600000`、`uniResidueTimeoutMs: 300000`、`uniToolTimeoutMs: 600000`。

### 4.1 `uni_list_installed`（只读）

枚举已装程序。参数：`query`（可选，按名称/发行商模糊过滤）。输出 schema：`kind: 'uni-list'` + `apps[]`（名称、版本、发行商、卸载键路径、是否 MSI、是否 Store 应用、是否有静默卸载串）。

### 4.2 `uni_uninstall`（破坏性，走审批）

参数：`appKey`（卸载注册表键的引用标识）+ `silent`（bool，默认 true）。

执行链（与 02 `ops_clean` 同款纪律）：

1. 重新枚举并定位 `appKey`——**不信任模型转述的程序名**，找不到即返回 `uni-not-found`。
2. 优先 `QuietUninstallString`，其次 MSI（`msiexec /x {GUID} /qn /norestart`），再其次 `UninstallString` + 常见静默参数白名单（`/S /SILENT /VERYSILENT /qn`——参数因安装器而异，脚本内置映射表，不在表内的必须退回交互确认）。
3. 执行前过审批服务：`approval.request({ reason: '即将卸载 <名称> <版本>，静默参数：<...>' })`，仅 `allowed-once` 继续，否则 `uni-denied`（fail-closed，对齐 02）。
4. 启动卸载进程 → 等待退出码 → 超时按 `uniUninstallTimeoutMs` 杀进程 → 结构化返回（exitCode/timedOut/stdout/stderr）。
5. 返回 `kind: 'uni-uninstalled'`（含退出码、是否成功、建议的下一步残留检查）。

### 4.3 `uni_clean_residue`（破坏性，走审批）

参数：`appName`。扫描残留并**预览 → 审批 → 执行**三段（完全对齐 02 的预览/确认模式）：

- 扫描域：`%AppData%`、`%LocalAppData%`、`%ProgramData%` 下的应用名匹配目录；注册表 `HKCU\Software\<发行商>` 残留键。
- 删除保护：桌面/文档/下载/图片永不碰（复用 02 的 `Test-Protected` 前缀判定）。
- 默认预览（`execute=false`）只出清单+大小；`execute=true` 且审批通过才删。
- 返回 `kind: 'uni-residue-preview' | 'uni-residue-executed' | 'uni-denied'`。

### 4.4 `uni_tool_list` / `uni_tool_run`（B 层调度，收录后才暴露）

与 03–15 调度插件同构：列知识库 `verified:true` 且 `schedulable:true` 的条目；运行走 runner（退出码/报告结构化返回）。收录前知识库为空 → 工具存在但列不出东西（fail-closed）。

## 5. PowerShell 脚本设计（assets\uninstall.ps1）

命令面：`-List [-Query <str>]` / `-Uninstall -Key <regKey> -Silent` / `-Residue -App <name> [-Execute]`。**参数面最小化，白名单/保护根/静默参数表全部锁死在脚本里。**

关键实现点：

1. **枚举**：`HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*`、`HKLM:\SOFTWARE\WOW6432Node\...\Uninstall\*`、`HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*` + `Get-AppxPackage`。跳过 `SystemComponent=1` 和空 `DisplayName` 条目。
2. **静默参数映射表**（内置，可扩展）：MSI → `/qn /norestart`；NSIS → `/S`；InnoSetup → `/VERYSILENT /NORESTART`；InstallShield → `/s /f1<应答文件>`（无应答文件则拒绝静默，退回交互）；未知 → 不猜测，返回「需交互卸载」。
3. **卸载进程管理**：`Start-Process -PassThru -Wait` + 超时 `WaitForExit(ms)`，超时杀进程并报 `timedOut`。
4. **结果判定**：退出码 0 或 3010（重启待定）视为成功；1641（成功且需重启）也归成功；其余回传退出码给模型判断。
5. **残留扫描**：`-Residue` 只读扫描返回 `path|size|exists` 行；`-Execute` 才删除，且每行删除前过 `Test-Protected`。
6. 输出行格式：`app:|key:|uninstall:` / `residue:` 前缀行，由 `lib\parse.js` 解析（可独立单测，对齐 01/02 的 parse 模式）。

## 6. BCUninstaller 收录（B 层，待实测）

### 6.1 三条准入留档（模板）

| 准入 | 证据 | 状态 |
|------|------|------|
| ① 能力不可达 | PowerShell 做不好的：深度残留扫描、孤儿程序检测、批量无人值守卸载、安装监控。枚举/基本卸载 PowerShell 可达，故 B 层定位为增强 | ✅ 已论证 |
| ② 授权干净 | Klocman/Bulk-Crap-Uninstaller，**Apache-2.0**（GitHub 页面明确 "licensed under Apache 2.0"，允许商业使用+再分发）；随附 LICENSE 文件进 `tools\bcu\` | ✅ 已核实 |
| ③ 机器可读接口 | CLI 参数/退出码/日志 **待实测**（见 6.2） | ⬜ 待实测 |

### 6.2 实测清单（按序执行，留档进 `audit.cliEvidence`）

1. 下载：GitHub releases 选 **Portable（self-contained）变体**——不依赖 .NET runtime 是硬要求（版本线选择：v6 需 Win10+/.NET8，自包含变体已内嵌运行时；若体积/兼容有顾虑，评估 v5.9 线）。
2. 本地解压 → `BCUninstaller.exe /?` 记录完整 CLI 参数表。
3. 实测无人值守模式：命令行直接指定目标应用 → 记录是否弹 UI、退出码约定（0/非0 语义）。
4. 实测列表驱动：能否 `--load <列表文件>` 批量执行。
5. 实测日志/报告导出：能否把卸载结果写文件或 stdout，格式是否可解析。
6. 离线验证：断网环境跑通一次全流程（确认无更新检查/遥测弹窗阻断自动化）。
7. 全部通过后：填 `audit.cliEvidence` → 条目 `verified:true`、`schedulable:true` → 移入 `uninstaller-tools.json` → 二进制 + LICENSE 落 `tools\bcu\`。

> 参考先例：03–15 插件当前 40 条候选全部 `verified:false`（fail-closed），本条从候选起步，流程一致。

## 7. 应用场景与提示词

| 场景 | 提示词（复制进 TUI） |
|------|---------------------|
| 卸载软件 | 帮我卸载 <软件名>，先列出你找到的匹配程序（名称+版本+发行商），确认是哪个再动手，执行前把卸载方式告诉我。 |
| 卸载+清残留 | 卸载 <软件名> 后，扫描它在 AppData 和注册表里的残留，先给我预览清单和大小，我确认后再删。 |
| 只查不删 | 这台电脑装了哪些软件？按发行商/大小列个清单，不要做任何修改。 |
| 卸载不干净（B 层收录后） | 用深度工具扫一遍 <软件名> 的残留和孤儿程序，先出报告。 |

## 8. 安装方法

```bat
cd dsh
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-uninstaller
pnpm dsh --profile dsh-tui --dump-config     :: 出现 "# == only-u-uninstaller" 层即成功
:: 纯 harness：dsh plugin --profile ops add ..\plugins\only-u-uninstaller
```

烤盘注意（对齐 4.7）：本地路径安装生成 junction，烤 U 盘前用实体目录 robocopy 覆盖 `node_modules\only-u-uninstaller`，或 `pnpm pack` 成 tgz 再装。
