# ⑧ U盘打包迁移

## 1. 概述

功能域：**交付与部署**。把整个 Only-U——deepseek-harness 内核 + 全部 npm 依赖 + 已装好 01–15 全部插件的 profile + **便携 Node.js**——整体烤进 U 盘。客户机不装 Node、不装 pnpm、不配任何环境，插盘双击 `Start-Agent.cmd` 就有一个 AI 运维助手。

- 形态：项目脚本（非 dsh 插件），`scripts\bake-usb.ps1` + `portable\` 目录族
- 开发状态：脚本与启动链路已有，待完成第一次真实烤盘验证

## 2. 构成

```
scripts\
  bake-usb.ps1                 # 烤盘脚本（开发机执行一次，产出 U 盘包）
portable\
  start.cmd                    # U 盘 TUI 入口：fail-fast 校验 + Key 中文提示安全输入写 .env
                               #   + 便携 node.exe 启动 dsh --profile dsh-tui
  diagnose.cmd  clean.cmd      # 离线脚本入口（无 Node 也能跑）
  .env.example                 # DEEPSEEK_API_KEY= / DEEPSEEK_BASE_URL=（真实 .env 被 gitignore）
  runtime\                     # 烤盘产物（gitignore，由 bake 生成）：
    node\node.exe              #   便携 Node（^22.19 || >=24）
    dsh\lib\bin.js             #   deepseek-harness 扁平 CLI（pnpm deploy --legacy 产物）
    dsh\node_modules\          #   全部依赖（~180MB，扁平无符号链接）
    dsh\profiles\dsh-tui\      #   profile 整目录（目标形态含 01–15 各插件；当前烤盘仅含 only-u-bundle，各插件过审后逐个装入）
    dsh\skills\only-u-ops\     #   06 的 SKILL.md（兼容路径）
盘根（烤盘后）:
  Start-Agent.cmd               # 英文名包装器（最稳）
  启动Agent.cmd  诊断.cmd  清理预览.cmd   # 中文入口
  CONTEXT.md                    # 领域术语（agent 开场先读）
```

## 3. 应用场景（什么时候用得上）

| 场景 | 说明 |
|------|------|
| 给客户/家人交付 | 对方电脑出问题 → 插盘双击 Start-Agent.cmd → AI 运维助手直接开工，全程零安装 |
| 批量分发 | 一台开发机烤出标准盘，任意多台机器复用同一套环境 |
| 开发机自测 | 烤盘后在自己机器上冒烟，验证全链路（本场景也是开发任务的一部分） |

## 4. 使用方法

**开发机（烤盘）**：

```bat
cd dsh
pnpm install && pnpm run build
:: 装壳 + 各插件（见 01-15 分册安装命令）
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-diagnose
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-clean
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-diagnose-tools
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-disk-repair
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-system-repair
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-ops-skill
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-disk-benchmark
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-hw-monitor
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-stress-test
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-network
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-screen
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-peripheral
pnpm dsh plugin --profile dsh-tui add ..\plugins\only-u-sys-maintain
powershell -File ..\scripts\bake-usb.ps1 -Dest F:\Only-U


> 注：`pnpm dsh plugin add` 在 dsh 工作区脚本通道异常（如 lefthook postinstall 失败）时的等价手工做法：
> 在 profile 目录（`%USERPROFILE%/.dsh/profiles/dsh-tui`）执行 `CI=true pnpm add file:E:/AI WORK/Onyl-U/plugins/<包名>`，
> 再把包名追加进 package.json 的 `dsh.profile.bundles`。插件包须为**实体目录**（FAT32 无 junction）。
```

**客户机（用盘）**：双击 `Start-Agent.cmd` → 没有 Key 时中文提示粘贴（隐藏输入，写 `.env`）→ 拉起 TUI。启动失败 → 中文提示指向 `诊断.cmd` 离线路径。

## 5. 打包清单（什么进盘、什么不进盘）

**进盘**：
| 内容 | 来源 |
|------|------|
| deepseek-harness 扁平 CLI + 全部 npm 依赖 | `pnpm deploy --legacy` 产物（含 vendored Cordis 补拷） |
| dsh-TUI 壳 + 01–15 各插件 | `%USERPROFILE%\.dsh\profiles\dsh-tui` 整目录 |
| 便携 Node | 烘焙脚本指定版本拷入 |
| SKILL.md | `.dsh\skills\only-u-ops` |
| portable 脚本 + 盘根启动器 + CONTEXT.md | 仓库骨架 robocopy |
| `.env`（Key） | 首次启动用户输入，写在盘上 |

**不进盘**：dsh 源码目录与 `dsh\node_modules` 整包（1.3GB+，会涨成数 GB）、`dsh-tui\` 源码快照、docs、.git、wxcontext（微信导出，涉隐私）。

## 6. 开发要点

### 6.1 bake-usb.ps1 现有流程（对照源码 scripts\bake-usb.ps1）

1. `pnpm deploy --legacy --prod` 打出扁平 CLI 到 %TEMP% 暂存区（无符号链接）。
2. 补拷 vendored Cordis 与 workspace 包（deploy 漏掉的嵌套链接包）。
3. 对盘上 `dsh-app-boot` 的 `ensureSymlink` 做**文本级 patch**（FAT32 无符号链接，EISDIR/EPERM 时跳过）——只改盘副本，不改仓库 `dsh\`；patch 失配应 fail-fast。
4. robocopy 仓库骨架（portable 脚本 + 盘根启动器，排除 dsh/dsh-tui/docs/.git）。
5. robocopy 暂存区 → `runtime\dsh`。
6. robocopy `%USERPROFILE%\.dsh\profiles\dsh-tui` → `runtime\dsh\profiles\dsh-tui`。
7. 拷贝 SKILL.md → `runtime\dsh\skills\only-u-ops`。

### 6.2 与插件系统相关的烤盘风险（开发必读）

- **本地插件的 `link:` junction**：`pnpm dsh plugin --profile dsh-tui add ..\plugins\<x>` 在 profile 的 node_modules 里建 junction。步骤 6 的 robocopy `/E` 不带 `/SL`，FAT32 也存不了 junction。
  - 缓解（推荐）：步骤 6 之后，对每个本地插件包做**实体目录 robocopy** 覆盖 `$profDst\node_modules\<包名>`（插件包内全是实体文件，拷过去即用）。
  - 备选：`pnpm pack` 打成 tgz 再 `plugin add .\xxx.tgz`（真实文件安装，天然无 junction）。
- **烤盘后插件验证**：客户机（或干净机器）`--dump-config` 应出现 `# == only-u-*` 各层；对话触发 `ops_diagnose` 确认工具可用。
- **第三方工具进盘通道**：03/04/05/09–15 各调度插件的 `tools\` 目录随包分发（实体文件，无 junction 问题），无需额外 robocopy 清单。

### 6.3 开发任务清单

1. 完成第一次真实烤盘：`cd dsh && pnpm install && pnpm run build` → 装插件 → `bake-usb.ps1 -Dest F:\Only-U`。
2. 落地 6.2 的本地插件实体目录 robocopy 覆盖逻辑。
3. 客户机冒烟：双击 Start-Agent.cmd → TUI 起 → `ops_diagnose` 跑通 → 无网路径 `诊断.cmd` 跑通。
4. 03/04/05/09–15 各调度插件的 `tools\` 目录随包进盘，无需额外处理。
