## 一、分支 `feat/2-diagnose-scan-cap` 代码安全审查结论

**结论：未发现达到上报门槛（置信度 ≥8/10）的可利用安全漏洞。分支可以合入。**

### 1.1 唯一候选发现（已被过滤）

**间接提示注入：诊断输出中的攻击者可控字符串进入模型上下文**
- 位置：[diagnose.ps1:103-111](../../portable/diagnose.ps1#L103-L111)（Top-5 进程名）、[diagnose.ps1:169-176](../../portable/diagnose.ps1#L169-L176)（PnP 设备名）、[SKILL.md](../../.dsh/skills/only-u-ops/SKILL.md)（会话开始强制运行诊断）
- 机制：USB 设备描述符字符串/进程可执行文件名是攻击者可构造的自由文本，作为"机器数据"进入 LLM 上下文，可能诱导 Agent 执行清理或命令
- **过滤理由（置信度 2/10）：**
  1. 攻击者模型不成立——能植入恶意 USB 设备或已驻留恶意软件的对手，本身就拥有这台机器，无需借道 LLM；产品由机主本人在场交互使用
  2. 人工闸门真实且默认拒绝——DSH 沙箱 `workspace-write` + 审批策略 `ask`，`clean.cmd -Execute` 目标（系统临时目录）在沙箱外，需 `sandbox_permissions` 升级且经 TUI 审批面板逐条展示完整命令文本，无"始终允许"，Esc 即拒绝，缺响应者则失败关闭（`unavailable`）
  3. 最坏影响有限——[clean.ps1:25-30](../../portable/clean.ps1#L25-L30) 仅允许清单内临时目录，且删除保护根覆盖桌面/文档/下载/图片

### 1.2 未达门槛的近似项（排除原因从简）

- 机器遥测流向第三方模型 API 的增量扩大——产品固有、用户主动发起的数据流，属隐私权衡而非可利用漏洞
- PS 5.1 回退路径枚举跟随符号链接——8 秒超时兜底、仅暴露聚合字节数，无内容读取
- 终端转义序列注入——影响面依赖终端配置，实际影响低

### 1.3 对 diff 本身的正面确认

- 新增 UNC 路径拒绝（[diagnose.ps1:16-18](../../portable/diagnose.ps1#L16-L18)）、扫描上限/超时（20000 文件/8 秒）、跳过重解析点（当前工作区版本）——均为防护性改进
- `Get-DirSize` 仅接收 `$candidates` 固定路径，无 glob 展开、无注入面
- SKILL.md 强化了"清理须明确确认"约束（[SKILL.md:15](../../.dsh/skills/only-u-ops/SKILL.md#L15)）
- 测试文件 [diagnose.Tests.ps1](../../portable/tests/diagnose.Tests.ps1) 无安全问题

### 🟠 高 2：诊断数据流向第三方 AI 服务，缺告知同意与脱敏（PIPL）

当前构建（TUI 路径）中，[diagnose.ps1:69-72](../../portable/diagnose.ps1#L69-L72) 输出计算机名、用户名；[diagnose.ps1:145-150](../../portable/diagnose.ps1#L145-L150) 输出事件日志消息原文（截断 120 字符，可能含用户名、文件路径）；本分支又新增进程名（[L103-111](../../portable/diagnose.ps1#L103-L111)）与设备名（[L169-176](../../portable/diagnose.ps1#L169-L176)）。[SKILL.md](../../.dsh/skills/only-u-ops/SKILL.md) 要求会话开始即运行并展示给 Agent——这些数据随模型请求发送到 AI Ping/DeepSeek。

- **定性：** 向第三方（委托处理方）传输含个人信息的数据，须满足 PIPL §17 告知与 §13 同意；在公司/学校电脑上还叠加组织数据保护义务。长 PRD 的 FR-006（启动告知）与 NFR-003（脱敏）已设计但**未在本场构建中实现**；本分支扩大了采集面而未同步增加脱敏
- **缓解：** 黑客松演示机为自有设备，风险可控；但"产品化"叙事下这是首要合规缺口。建议：启动横幅加一句授权/隐私声明（一行即可）；事件日志与设备名在进入模型前做字段级脱敏（用户名→`user`、路径段折叠）；启动项已只报数量（[L113-115](../../portable/diagnose.ps1#L113-L115)），符合最小化原则，值得推广到其他字段
- **无需担心的部分：** AI Ping（aiping.cn）与 DeepSeek 均为境内服务，**不涉及数据出境**（PIPL 第三章不触发）

## 四、总体结论

1. **分支代码安全**：`feat/2-diagnose-scan-cap` 的改动本身是防护性收敛（扫描上限、超时、UNC 拒绝、清理确认强化），经识别与对抗性过滤后无高置信度可利用漏洞——分支可以合入。

### 5.1 代码安全复查结论

**结论：未发现达到上报门槛（置信度 ≥8/10）的安全漏洞。该分支可以合入。**

新增代码全部为只读、当前用户权限、参数全部为固定字面量或系统遥测数据，无任何注入面。经对抗性过滤排除的近似项：

- 各查询调用（`Get-WinEvent`/`Get-CimInstance`/`Get-Counter`/`Get-PhysicalDisk`/`Get-StorageReliabilityCounter`）参数均为硬编码字面量，无不可信输入——不构成注入
- Provider 白名单正则 `'^(storahci|stornvme|iaStor.*|Disk)$'` 应用于系统事件元数据且锚定线性，无 ReDoS、无伪造路径（伪造 System 日志需管理员权限＝日志欺骗，下游仅为控制台输出与人工审批闸门后的 Agent）
- 事件消息截断 `Substring(0, 280)` 有长度守卫；`CounterSamples[0]` 空采样由 try/catch 降级——均为健壮性问题而非安全问题
- 红灯区阈值逻辑仅 `Write-Output` 展示、脚本不据此动作——不可诱导破坏性行为
- SMART 区**刻意未取** `SerialNumber`/`UniqueId`/`FirmwareVersion`/加密状态——良性硬件盘点
- 新测试仅只读执行真实脚本、输出入变量、finally 恢复环境变量——CI/开发机安全

### 5.2 合规增量分析

| 变化 | 定性 |
|---|---|
| 事件采集从"任意 System 错误（近 3 天）"收窄为 5 个特定事件 ID + Provider 白名单（近 7 天、展示上限 20 条） | ✅ **正向**：目的限定 + 最小必要（PIPL §6），比上一版更符合数据最小化原则 |
| 事件消息截断从 120 放宽到 280 字符；事件 2004 消息可含进程路径（可能含用户名路径段） | ⚠️ 轻微扩大：进模型前的字段级脱敏建议（本报告 §二.2）仍然成立 |
| SMART 采集（磁盘型号/健康/温度/读错误数，无序列号） | ✅ 硬件盘点类数据，敏感度低；未采集序列号是正确取舍 |
| 新增 commit/pagefile/计数器指标、红灯区展示 | ✅ 纯系统指标，无个人信息；全部只读，无新增写入/删除/执行能力 |

**本轮合规结论：无新增合法风险，事件采集最小化方面有实质改进。** 其余结论（§二.2 告知同意与脱敏缺口、§二.3 许可缺口、§二.4 Key 条款、§二.5 双用途合规）维持不变。
