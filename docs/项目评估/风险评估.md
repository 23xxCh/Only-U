## 🔴 高风险（赛前必须处理）

### H1. 公开仓库泄露在有效期内的凭据（P0，最优先）

[突击深圳黑客松_聊天记录.md](../requirements-source/突击深圳黑客松_聊天记录.md) 随 commit `42b0ed2` 推送到**公开仓库**。队友合规报告逐行核实：**ToDesk 远程控制设备码+临时密码（2737-2742 行）、民宿房门密码+WiFi 密码（4433-4465 行，事件进行中）、支付交易号、含身份证复印件的快递描述**——不是"潜在泄露"，是**任何人都能现在使用**的活跃凭据。另含 35 处以上手机号/wxid/邮箱，且其中还有被否决的攻击工具讨论片段。

**建议（按队友报告 P0 清单执行，立即）**：① 失效 ToDesk 凭据、更换房门密码；② 删除文件并**重写 git 历史**（仅删除不够）；③ 仓库无法重写则临时转私有。

（注：bake-usb.ps1 第 2 步仍会把该文件拷进演示 U 盘，整改时一并把 `docs\requirements-source` 加入 bake 的 /XD 排除列表。）

### H2. 烤盘全链路零验证 + 前置条件未满足

实测当前开发机：`dsh\node_modules` ✗、`dsh\apps\cli\lib\bin.js` ✗（从未 build）、`portable\runtime\` ✗（从未烤盘）。[bake-usb.ps1:20-24](../../scripts/bake-usb.ps1#L20-L24) 的两个 fail-fast 断言现在**第一步就挂**。另外：

- 烤后校验仍只跑 `--help` 不带 profile（[bake-usb.ps1:223-225](../../scripts/bake-usb.ps1#L223-L225)），profile 的 pnpm junction 会被 robocopy 静默跳过 → 开发机正常、U 盘上起不来的风险仍在
- 好消息：`%USERPROFILE%\.dsh\profiles\dsh-tui`（含 node_modules）**已存在**（队友调研时还不存在，状态已推进）——但若烤盘发生在另一台机器，需在**那台机器**上确认

**建议**：按 AGENTS.md 顺序 `cd dsh && pnpm install && pnpm run build` → 烤盘 → 从 $Dest 直接跑 `node portable\runtime\dsh\lib\bin.js --profile dsh-tui --help` 冒烟 → 干净机器实测。今天内必须完成第一次真实烤盘。

### H3. 仓库版 start.cmd 仍与架构冲突 + 烤盘内嵌副本存在双份漂移

Issue #2 已合并 ✓，但 [portable/start.cmd:37-43](../../portable/start.cmd#L37-L43)（main 与各分支相同）仍是 pnpm + `--profile headless` 旧实现；Issue #1 分支已推远程（新提交 444dd91）但**未合并**。新增发现：**bake-usb.ps1 第 151-208 行内嵌了一份 start.cmd here-string**，与仓库版是两份独立副本——即使 Issue #1 合并修好了仓库版，**烤盘产物里的 start.cmd 不会自动获得交互式粘贴 Key 的能力**，除非有人同步改 bake 脚本。当前两份都没有 Key 输入兜底。

### H4. Key 仍缺失，TUI 路径无法启动

`portable\.env` 仍不存在（只有 [.env.example](../../portable/.env.example)）。当前烤盘产物遇到空 Key 直接 `goto :fail`（[bake-usb.ps1:188-192](../../scripts/bake-usb.ps1#L188-L192)），无交互兜底 → 现在烤盘，有网路径必挂。演示 U 盘会明文携带团队 Key（见队友报告"团队共享 API Key 与服务条款"一节），赛后需轮换。

**建议**：烤盘前把限额 Key 放入 `portable\.env`；赛后立即轮换。

### 🆕 本轮新代码（feat/6-diagnose-key-metrics）审查结论

整体评价：**质量明显提升**。ReparsePoint 跳过、UNC 拒绝保留、PnP 改用 `ConfigManagerErrorCode`、事件按 ProviderName 过滤防误报（测试断言排除 Miniport NIC/Hypervisor ✓）、红灯区摘要对演示友好。新增低风险项：

1. **Get-Counter 计数器名本地化**：`\Memory\% Committed Bytes In Use`（[diagnose.ps1:96](../../portable/diagnose.ps1#L96)）在非英文 Windows 上计数器路径是本地化的，可能读不到——已有优雅降级（打印"无法读取"），**建议在演示机实测是否命中该指标**（测试的 `*Committed Bytes In Use*` 断言两种路径都通过，设计得好）
2. **最坏用时**：5 个 Start-Job（每个最高 8 秒超时）+ 进程派生开销 + Get-Counter 首调用 + SMART 管理员权限探测，慢机器上可能超出「60 秒内结束」的承诺（现有测试只对单个大 TEMP 场景断言 <60s）——演示机实测一次总时长
3. **超时后统计丢失**：`Skipped` 现在报 0 个文件（[diagnose.ps1:55-57](../../portable/diagnose.ps1#L55-L57)），不再报部分统计——纯展示问题
4. **Start-Job 每次扫描派生一个子进程**（共 5 个）：在启用 WDAC/ASR 拦截子进程的机器上扫描会整体报 Skipped/Unreadable——降级优雅，接受即可
5. **feat/6 分支已推送且与 origin 同步** ✓；PR 状态未知（gh 不可用）——bake 拷的是工作区当前 checkout（含新 diagnose），所以**烤盘不依赖 feat/6 是否合并**，这一点比第一轮判断乐观
