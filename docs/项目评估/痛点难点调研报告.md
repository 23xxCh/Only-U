### 2. 仓库内 start.cmd 漂移：已修复合入（关闭）

【复评二】PR #4（`feat/1-portable-start-baked-node`）已合入 main（`bfb5c0f`）：仓库内 [portable/start.cmd](../../portable/start.cmd) 现为 ADR-0005 形态（fail-fast 检查 node.exe / bin.js / profile、SecureString 隐藏输入 Key、Key 写入 `portable\.env`、DSH_HOME 指向盘上 runtime），附根目录 Start-Agent.cmd 包装器与 298 行自研测试（csc 编译 StubNode 假 node.exe，无 Pester 依赖，用 GBK 编码读取验证 .cmd 编码）。初评 P0-2 关闭。

**遗留风险（现已上 main）**：start.cmd 的 `ping -n 1 -w 2000 223.5.5.5` 网络门。Issue #1 票面没有这条；ICMP 在酒店/企业网络常被禁，会导致 HTTP 明明可用却误判「无网」挡住 TUI 路径，且每次启动白等最多 2 秒。**建议烤盘前删掉 ping 门（或改为 HTTPS 探测）**——这是当前演示链路里最便宜的一次修复。

### 3. 现场不确定因素密集（聊天记录证实）

无网（酒店网络可能受限）、Key 归属未决、token 预算焦虑——不变，见 [requirements-source/突击深圳黑客松_聊天记录.md](../requirements-source/突击深圳黑客松_聊天记录.md)。对策仍在：Approach A 纯脚本保底 + skill 铁律。

## P1 · 工程难点

### 4. 烘焙链路复杂度（不变，仍是最大未验证块）

FAT32 无符号链接/无 junction → `pnpm deploy --legacy` + [bake-usb.ps1:35-68](../../scripts/bake-usb.ps1#L35-L68) 手工补 vendor/workspace 包 + 对 `dsh-app-boot/lib/index.js` 字符串替换 patch（[bake-usb.ps1:70-108](../../scripts/bake-usb.ps1#L70-L108)，失配只警告不失败）。实测 pnpm 11.22 仍支持 `deploy --legacy`；整个 robocopy 流程仍未跑过一次。建议 patch 失配改为直接失败。

### 5. 三种文件三种编码：已从口头约束变成测试门禁（缓解）

- `.cmd` GBK/ANSI 无 BOM；`.ps1` UTF-8 带 BOM；运行期 `[Console]::OutputEncoding = UTF8`。
- 【复评二】两套测试现在都在断言编码：PR #4 的启动器测试用 `GetEncoding(936)` 读 .cmd 验证中文可解码 + 无 BOM；feat/8 的 clean.Tests.ps1 有专门用例「keeps clean.ps1 as UTF-8 with BOM and clean.cmd as GBK without BOM」。实测 feat/8 的 clean.ps1 头三字节 `ef bb bf` ✓。

### 6. 上游 0.x rc 漂移风险（不变）

dsh `0.1.1-rc.2` 与 dsh-tui `0.8.8` 契约线吻合（已实证 `dsh --help` 可引导）；[dsh-tui/ADAPTER.md](../../dsh-tui/ADAPTER.md) 契约面（23 disables / 14 inserts / 6 overrides）+ bake 的 boot 字符串 patch 构成双重耦合；[dsh/UPSTREAM.md](../../dsh/UPSTREAM.md) 注明 clone 因 schannel EOF 失败只能 zipball 导入。

### 7. 安全边界：治理层已就位，实现层出现一个需要拍板的新点

- 【复评二】main 新增 **ADR-0006（Agent 权限分级）**：按可逆性分 🟢绿（全自动）/🟡黄（会话级一次授权）/🔴红（逐项确认+预览+日志）；明言 V1 不改代码、`-Execute` 是唯一门（红级）；并规定赛后扩容票必须标注落在哪级。这正好补上了初评「沙箱缺失、安全边界全靠脚本层」的治理框架。skill `only-u-ops` 尚未按 ADR-0006 更新措辞（ADR 自己写「后续更新时」）。
- 【复评二】main 新增 **ADR-0007（第三方工具政策）**：PowerShell 优先、单工具插件三条准入（能力不可达 / 授权可商业重分发 / 机器可读接口）；否决图吧工具箱类整体引入，理由充分（GUI 自动化脆、授权雷区、杀软误报、定位错位）。
- **新冲突点（PR #12）**：feat/8 的 clean.ps1 新增「清空回收站」（`Clear-RecycleBin`）。ADR-0006 的核心原则是「让动作可逆，好过加确认」，回收站正是"删除可逆"的机制本身；清空它 = 把用户最后一道后悔药销毁。虽走预览 + `-Execute`（红级合规的字母），但与 ADR-0006 的精神相悖，也与需求调研「用户最怕删错文件」的定位相反。**建议队长在评审 PR #12 时明确：回收站类别删除或改为默认不勾选/年龄门。**
- clean.ps1 其余安全细节保持：protected roots 前缀匹配、预览默认、重解析点跳过（删除空目录时）、锁定文件跳过计数。

### 8. 诊断脚本：质量已达标（PR #10 待合入）

- `feat/2` 已合入（PR #5）：Start-Job 可取消扫描、跳过 ReparsePoint、PnP 用 `ConfigManagerErrorCode` 精确过滤。
- `feat/6-diagnose-key-metrics`：**已推送（origin/feat/6-diagnose-key-metrics），PR #10 开放**，本地与远端同步。内容：提交内存 %（Get-Counter）、pagefile、SMART、关键事件按 Provider+Id 收紧（2004 / Disk 7·153·157 / storahci·stornvme·iaStor 129）、顶部红灯区汇总、进程按 commit 排序；diff 仅动 diagnose.ps1 + 测试 + 一张队友说明文档，与 main 无冲突。
- 实测：直接运行 4.4–5.1 秒；Pester 7/7 通过（28.7s）；受限环境下各段优雅降级为「无法读取」不崩。
- 残留小点：SMART 的 read-errors/temperature 在本机 n/a（已优雅降级）；Pester 3.4 很老。

### 9.（新增）PR #12 / feat/8-clean-whitelist-log 评估

clean.ps1 重写为 5 类白名单 + 年龄门 + 日志（+324 行），工程水准高：

| 类别 | 年龄门 | 评估 |
|---|---|---|
| TEMP（4 个临时目录） | **7 天门**（新文件跳过） | ✓ 核心类别，门限合理 |
| 缩略图缓存（thumbcache_*.db） | 无（系统自动重建，无所谓） | ✓ 安全 |
| WER 报告（4 个目录） | **无** | △ 崩溃转储是查蓝屏的证据，产品定位「读得出蓝屏」，建议也加年龄门（如 30 天） |
| Windows Update 下载缓存 | 无（脚本注明需重下） | △ 可接受（预览+确认兜底） |
| **回收站（Clear-RecycleBin）** | 无 | ⚠ 见第 7 条：不可逆、与 ADR-0006 精神相悖，建议砍掉或降级为默认不做 |

其它：`-Execute` 后写 `portable\logs\clean-时间戳.log`（UTF-8 无 BOM，含删除路径清单，留在 U 盘不上传，可接受）；计划/实际偏差 >10% 打 WARNING；空目录清理跳过 reparse point；`$script:categoryResults` 收集后未展示（死数据，小瑕疵）。测试：clean.Tests.ps1 5 个用例，评估环境实测 4/5 通过（1 项失败是抽取环境缺 clean.cmd 的文件缺失，非代码问题）；「execute 删除 + 写日志」用例通过。**白名单从「仅临时目录」扩到 5 类，属于范围扩大，需要队长在 Issue #8/PR 评审里明确拍板**（ADR-0002 的「白名单」定义尚未更新）。
