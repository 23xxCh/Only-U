## 1. 设计结论

Only-U 是装载在普通 U 盘中的 Windows 运维 Agent。V1 完整支持 Windows 10 与 Windows 11，不购买或依赖无线网卡、流量卡、BadUSB、PE 启动盘、专用安全芯片或本地推理硬件。用户把 U 盘插入能够正常进入 Windows 桌面的电脑，双击启动程序后，通过本地 Web 界面描述故障、查看诊断证据、批准修复方案并导出运维报告。

Only-U 采用 DeepSeek Harness 的 Profile、Bundle 与 Cordis 插件机制构建，不直接修改 Harness 的 agent loop、工具管线或其他核心包。Only-U 新增的主机探测、Windows 运维、风险控制、恢复点、报告导出、联网门禁、U 盘凭据读取和品牌界面都以可装卸插件实现。DeepSeek Harness 的现有会话、凭据、设置、DeepSeek Chat Completions 适配器、PowerShell、文件系统、Windows ACL 沙箱、审批策略与 Web 应用继续作为基础能力。

V1 是在线产品。启动后必须先检查到 AI Ping 接口的可用网络；无网络、DNS 失败、TLS 失败、接口不可达或凭据认证失败时，不进入 Agent 会话，不执行离线诊断或修复，只显示明确原因、重试按钮和退出按钮。这一边界是产品决定，不把“离线修复”暗示成已具备能力。

## 2. 用户与场景

目标用户构成按 7:3 设计：约 70% 是公司 IT、桌面运维、技术支持、开发者和熟悉 Windows 的“搞机”用户，约 30% 是不能准确描述故障、但能在引导下完成插盘、双击、确认操作的普通用户。界面默认用普通用户可理解的语言解释现象和风险，同时保留命令、退出码、事件日志、设备实例 ID、驱动版本等专业证据供技术用户展开查看。

核心场景包括系统盘空间不足、电脑卡顿、进程或服务异常、打印机与常见设备驱动问题、Windows 更新异常、网络配置异常但仍能访问 AI Ping、蓝屏信息收集、文件定位与整理、Windows Defender 扫描、常见系统文件完整性检查、启动项分析和修复结果交付。每个场景都遵守“先采集、再解释、再计划、后执行、可复核”的统一流程。

Only-U 不负责无法进入 Windows、显示器完全无输出、BIOS 或固件损坏、物理硬盘损坏、硬件拆装、从 U 盘启动 PE、无人值守重装系统、绕过系统权限、远程植入、后门、凭据窃取、攻击扫描、自媒体自动化或通用办公自动化。macOS 与 Linux 在 V1 只保留适配接口和文档，不宣称可用。

## 3. 选择的架构方案

### 3.1 采用 DSH Bundle/Profile，而非修改内核

Only-U 发布一个 Windows 专用 Profile。Profile 叠加 DeepSeek Harness 基础 Bundle、Web App Bundle 和 Only-U 运维 Bundle，再由 U 盘上的部署配置覆盖端点、模型、工作目录、日志目录和权限默认值。Only-U 运维 Bundle 组装以下逻辑组件：

1. 启动与便携运行组件：解析 U 盘根目录，创建本次运行目录，检测 Windows 版本、架构、可写空间、网络、管理员状态和依赖完整性。
2. U 盘凭据组件：从 U 盘固定凭据文件读取团队统一 AI Ping Key，通过 DSH 凭据能力按引用提供给模型适配器。
3. AI Ping/DeepSeek 连接组件：复用 `llm-deepseek` 的 Chat Completions 适配器，将 Base URL 配置为 AI Ping，模型名由发布配置确定。
4. 主机事实组件：以结构化数据提供操作系统、磁盘、内存、CPU、设备、驱动、服务、事件、更新、防病毒、网络与崩溃转储摘要。
5. Windows 运维工具组件：以参数化工具执行受控 PowerShell、文件扫描、系统检查、Defender 调用、服务检查、设备与驱动查询等动作。
6. 风险策略组件：为每个动作分级，决定是否只读、是否要求确认、是否要求管理员权限、是否要求恢复措施和是否禁止执行。
7. 变更与恢复组件：生成执行前快照，记录具体变更，支持由产品定义的可逆动作回退；不可可靠回退的动作必须提前说明。
8. 报告组件：从会话事件与结构化运维事件生成可读报告和机器可读报告，保存到 U 盘。
9. Only-U Web 界面组件：提供启动检查、故障描述、诊断进度、证据、方案确认、执行进度、结果复核和报告导出页面。

这一方案使 Only-U 可以持续吸收 DeepSeek Harness 上游更新，同时把产品差异保持在插件与配置层。任何确实需要修改 Harness 的缺口都必须先证明现有扩展点无法满足，再单独提出上游兼容的最小变更；V1 设计不预设这种内核修改。

### 3.2 最高测试接缝

产品级验收以“组装后的 Only-U Profile”作为最高测试接缝。测试从启动器或本地 Web 客户端发起一个真实用户任务，使用可重放模型响应或本地模拟 AI Ping 服务，观察完整会话事件、工具审批、PowerShell 执行、UI 投影与报告输出。这样可以在一个接缝上证明组件是否真正协同，而不是只证明单个函数存在。

插件级单元测试只用于高风险的纯规则与解析逻辑，包括风险分级、命令参数构造、系统输出解析、路径范围判断、删除候选过滤、敏感信息脱敏、回退清单生成和错误分类。需要真实 Windows 行为的场景使用隔离虚拟机或可还原测试机执行端到端测试，不在开发者主机上制造危险故障。

## 4. 运行流程

### 4.1 启动阶段

用户双击 U 盘根目录中的 Only-U 启动程序。启动器不依赖浏览器能访问互联网，但需要系统能够启动本地进程和打开本地 WebView 或默认浏览器。启动器验证自身文件清单与版本，定位 U 盘运行根目录，拒绝把系统盘用户目录误当成产品数据根目录。

启动器随后执行联网门禁。门禁依次确认本机具备可用网络接口、DNS 能解析 AI Ping 域名、HTTPS 握手成功、模型端点能够返回受支持的响应，并验证凭据能通过认证。只有这些检查全部通过，才启动 DSH Profile 并开放新建会话。失败界面必须把“没有网络”“服务暂时不可达”“密钥不可用或额度不足”分开说明；用户只能重试、查看简短帮助或退出。

启动阶段以普通用户权限运行。需要管理员权限的诊断或修复在具体动作发生前触发 UAC，不把整个产品默认永久置于高权限。用户拒绝 UAC 后，会话继续保留，相关动作标记为未执行并给出权限原因。

### 4.2 诊断阶段

用户选择常见问题入口或自由描述故障。Agent 先提出最少量澄清问题，然后选择只读检查。所有模型可见的主机事实、工具调用、工具结果和用户批准都进入 DSH 会话日志，确保刷新页面、恢复会话、导出报告时能够重建当时的判断依据。

诊断结果必须区分事实、推断和建议。事实包含命令来源、采集时间、对象标识与原始值；推断包含置信度和支持证据；建议说明预期效果、影响范围、风险等级、是否需要管理员权限、是否可回退以及预计耗时。模型不能把一次命令失败解释成故障已确认，也不能在证据不足时直接执行修复。

### 4.3 方案与审批阶段

Only-U 将候选动作组织成可单独批准的修复计划。默认安全模式允许自动执行只读检查和明确低风险的临时文件清理，但所有删除用户文件、修改注册表、启停服务、修改启动项、重置网络、修复系统组件、安装或回滚驱动、隔离威胁、运行系统恢复等动作都必须展示影响并获得明确批准。

技术用户可切换到专家模式，减少低风险动作的重复确认并展开完整命令。专家模式不取消产品硬性禁令，也不能绕过系统权限、目标范围、备份要求和审计记录。任何“全自动”表述都只代表在既定白名单内自动编排，不代表模型拥有无限制终端控制权。

### 4.4 执行与复核阶段

执行器只接收结构化动作参数，不接收由模型自由拼接的高风险 Shell 字符串。涉及系统修改时，执行器在动作前采集对照值和回退材料，动作后运行验证检查。一个动作失败时，后续依赖动作默认停止；互不依赖的动作可继续，但报告必须准确区分成功、失败、跳过、用户拒绝和等待重启。

修复完成后，Only-U 重复关键诊断，展示前后对比，生成报告并提醒用户安全弹出 U 盘。需要重启才能验证的动作记录为“待重启验证”，不能提前宣称成功。产品不会在用户不知情时留下常驻服务、计划任务、远程控制组件或自启动项。

## 5. 安全与凭据设计

### 5.1 静态 U 盘密钥

用户已选择 B 方案：团队统一 AI Ping/DeepSeek Key 静态放入 U 盘。设计接受这一业务决定，但不得把真实 Key 写入 Git、Markdown、Cordis 配置、构建日志、崩溃报告、会话日志或 UI。发布流程在制作实际 U 盘时把真实 Key 写入专用凭据文件；仓库只保存文件格式、读取逻辑和无效测试凭据。

启动器把凭据文件解析为 DSH 凭据引用，模型适配器按请求读取。Only-U 不把 Key 传给 PowerShell 子进程，不把包含 Key 的环境整体继承给通用工具，不在错误信息中输出请求头。凭据文件可以设置隐藏、只读和当前 Windows 用户 ACL，但文档必须明确：普通 U 盘上的静态密钥无法防御能够读取介质的人，隐藏或混淆不等于密码学保护。

风险缓解依赖服务端额度、用途隔离、调用审计、定期轮换和丢失处置。团队应为 Only-U 单独创建 Key，设置固定或月度额度，不复用管理权限更高的个人 Key。U 盘丢失、Key 疑似泄露或调用异常时，运维人员必须能在 AI Ping 控制台禁用旧 Key，并制作含新 Key 的介质。

### 5.2 主机数据与隐私

Only-U 默认只上传完成当前推理所需的文本化证据。工具在返回模型前进行最小化与脱敏：不主动读取浏览器密码、凭据管理器、私人聊天数据库、SSH 私钥、完整文档正文或与故障无关的用户文件。用户名、主机名、IP、路径和事件日志可能包含个人信息，报告必须标识其来源并允许用户选择是否导出。

文件搜索默认只返回文件名、路径、大小和时间，不读取内容。只有用户明确要求且确认具体文件时，才读取必要片段。诊断缓存、会话数据库和报告全部写入 U 盘的 Only-U 数据目录；程序正常退出时清理系统临时目录中的本次运行残留。任何无法清理的文件都在退出页列出。

### 5.3 命令与文件安全

Windows ACL 沙箱在 DSH 中属于部分强制能力，不能被表述为完整安全边界。Only-U 还需要业务级动作白名单、结构化参数、目标规范化、符号链接与重解析点检查、系统目录保护、用户资料保护、容量阈值和审批策略。危险操作不能因为沙箱处于 `danger-full-access` 就自动变得安全。

删除采用候选清单、预估释放空间、保护规则、用户确认、隔离或回收优先、动作后核验的流程。默认禁止永久删除用户文档、桌面、下载、照片、视频、源码仓库和未知目录。注册表、服务、驱动与系统文件动作使用专用工具，不把可执行命令文本交给模型自由生成。

## 6. 数据与审计

每次运行生成唯一运行 ID，每个维修对象生成会话 ID。运行数据至少包括启动检查、版本、主机摘要、用户描述、澄清答复、诊断动作、证据、风险分类、批准记录、执行结果、错误、前后对比与报告信息。秘密值不进入任何事件；原始工具输出在写盘前执行脱敏和大小限制。

报告包含面向普通用户的结论、面向技术用户的证据附录和机器可读 JSON。报告写入 U 盘，默认不自动上传。用户可以删除本次记录；删除只作用于 U 盘中的选定运行目录，不清理其他历史。运行日志不可伪造成功：工具退出码、超时、权限拒绝、用户取消与重启待验证都使用不同状态。

## 7. 错误处理

错误分为启动、联网、认证、额度、模型、权限、工具、系统、存储、用户取消和产品内部错误。每类错误都有稳定代码、普通语言解释、技术详情、是否可重试以及推荐下一步。错误消息不包含 Key、Authorization 头、完整请求体或与当前故障无关的个人数据。

联网或模型连接在会话中途断开时，Only-U 停止发起新的模型步骤，保留已完成的本地工具结果，不自行继续高风险动作。用户恢复网络后可以重试当前步骤；若无法恢复，只能导出已有记录并退出。U 盘被拔出或写满时，产品停止变更动作，优先把最小错误信息写入系统临时区并提示重新插入原介质；恢复后再迁回，不能静默改用系统盘长期存储。

## 8. 测试设计

测试以外部行为为准，不断言私有函数或 Cordis 内部装载顺序。关键测试组包括：启动器在不同盘符运行；联网门禁的成功、DNS 失败、TLS 失败、401、429 与超时；Key 不出现在日志；普通权限与 UAC 拒绝；安全模式审批；专家模式仍受硬性禁令；磁盘清理候选保护；驱动与服务只读诊断；Defender 扫描；系统检查的退出码解析；工具超时与取消；U 盘写满和拔出；会话恢复；报告脱敏；Windows 10/11 不同语言与路径；模型发出恶意或越权工具参数时执行器拒绝。

产品级快照测试覆盖普通用户与技术用户看到的完整对话，包括诊断证据、确认卡片、失败提示和最终报告摘要。Windows 虚拟机端到端测试覆盖一个可安全制造并恢复的故障集合，例如临时目录膨胀、测试服务停止、无效 DNS、模拟打印队列卡住、受控系统检查结果和测试文件搜索。蓝屏、驱动回滚、系统还原等高风险场景主要使用录制输出和专用实验机验证，不在共享 CI 主机上直接制造。

## 9. 发布与演进

V1 先交付可演示、可验证的 Windows 在线运维闭环，而不是覆盖所有电脑故障。首个可用版本优先完成便携启动、联网门禁、静态 U 盘凭据、主机体检、C 盘分析、性能与服务分析、文件查找、Defender 调用、系统完整性检查、安全审批、报告导出和真实 Windows 测试。

后续版本可以增加更多驱动供应商集成、远程协作、离线规则库、WinPE、系统重装、macOS/Linux Provider 或专用硬件，但每项都需要独立设计、威胁分析和验收计划。V1 的插件边界为这些能力保留扩展位置，但不提前实现空壳功能。

## 10. 自审结论

本规格没有未决占位内容。产品边界与用户确认一致：Windows 10/11、普通 U 盘、在线-only、无网只提示、7:3 技术与普通用户、静态团队 Key、DeepSeek Harness 插件化改造。架构没有把 CC Switch 或 Codex 作为 Only-U 运行时依赖；它们仅可用于开发期验证。高风险动作、数据处理、凭据暴露、失败语义和测试接缝均已给出明确规则，没有将未购买硬件或离线能力写入 V1 承诺。
