# Agent 权限分级：按可逆性定门禁，不按危险感

编号 0006。回答一个会反复出现的问题：「这个操作要不要让用户确认？」

背景：V1 已锁定「只读诊断 + 白名单清理预览 + 一句确认」。赛后扩容（杀进程、装驱动、动服务、动启动项）时，如果每个动作都加一道确认，agent 会退化成「确认打字机」，用户进入确认疲劳（盲点确认，门等于没门）；如果都不加，误删/误改风险不可接受。业界（NN/g 确认规范、Anthropic agent 指南、Claude Code 权限模型）的共识解法是**按操作的可逆性分级**。

**Status:** accepted

## 三级模型

| 级 | 定义 | 门禁 | V1/V2 例子 |
|---|---|---|---|
| 🟢 绿 | 只读，无副作用 | **全自动**，不打扰 | 诊断、SMART、事件日志、进程列表、启动项枚举、PnP 枚举 |
| 🟡 黄 | **可逆**操作 | **会话级授权一次**，之后同类不再问 | 删除走回收站、重启 Spooler 服务、禁用启动项（可再启用）、结束用户进程（可重开） |
| 🔴 红 | 不可逆 / 系统级改动 | 逐项确认 + 预览 + 日志 | 永久删除（绕过回收站）、装/卸驱动、改注册表、清 WinSxS、重装系统 |

## 三条原则

1. **让动作可逆，好过加确认。** 想减门，先想办法把红改成黄（如：删除走回收站），而不是直接把红放行。
2. **预览清单即确认材料。** 展示了「将删除 X 文件 Y MB、路径清单」之后，确认动作本身就是看清单后的一句话，不需要二次弹窗。
3. **门要少而准。** 每道门必须对应真实不可逆风险。门越多，用户越会盲点确认，防护归零。

## 判定流程（新票开工前过一遍）

```
这个操作有副作用吗？
├─ 没有 → 绿，全自动
└─ 有 → 出错了能一键恢复吗（回收站/可再启用/服务可重启）？
    ├─ 能 → 黄，本会话首次询问，授权后同类放行
    └─ 不能 → 红，逐项预览+确认+日志
```

## 对当前实现的影响

- **V1 不改代码。** 现状已符合：诊断/预览全自动（绿），`-Execute` 是唯一的门（红），流程总共一次打字。
- 大批量 TEMP 删除保持硬删 + 日志（回收站逐文件 COM 调用在数万文件时太慢），属于「红但用日志+白名单补偿」。
- 赛后扩容的新票（杀进程、动启动项、驱动安装）在 PR 描述里必须写明「本操作落在绿/黄/红哪级、门禁怎么设计」，评审按此打分。
- skill `only-u-ops` 后续更新时，把三级模型写进「清理」章节：黄级操作首次询问、会话内不再重复确认。
