# Only-U 维修报告模板（REPORT-FORMAT）

AI 在 TUI 里复述报告时必须按本文件的两段结构输出：先师傅技术版，末尾主人白话版。落盘报告（`portable\save-report.cmd`）只收原始数据；白话版由 AI 生成后粘贴到报告尾部的占位段。

## 一、师傅技术版（TUI 对话中直接展示）

### 红灯区（置顶）

- 只列 diagnose.ps1 报告红灯区里命中的项，一条一行，前缀 `!`，沿用原文（如「C 盘空间严重不足（剩余低于 5% 或 1 GB）」）。
- 无命中：写「本次未见红灯项」，并省略清单。
- 每条红灯必须在后面对应小节有展开，不许只报不展开。

### 各小节：结论 → 证据 → 建议

按 diagnose 输出的顺序逐节复述：磁盘 / 内存 / 可回收空间 / 关键事件 / 打印机 / 即插即用设备 / SMART。每节固定三段：

1. **结论**：一句话判断——正常 / 预警 / 异常，及严重程度。
2. **证据**：指标数值，必须带单位（GB、MB、%、℃、次/7 天、MB/s）。数值引用 diagnose / clean 的原文，不凭感觉编数。
3. **建议动作**：可执行的下一步（如「跑 `portable\clean.cmd` 预览」「备份重要文件后送修检查 SMART」）。

术语保留原文（提交内存、WSD、SMART、pagefile……），不翻译、不发明同义词（词汇表见仓库根 CONTEXT.md）。

### 清理执行情况（本次执行过清理才写）

- 预计量 / 实际回收量 / 计划-实际偏差，引用 `portable\logs\` 最新 `clean-*.log` 的文件名。
- 未执行清理：写「本次未执行清理」。

## 二、主人白话版（报告末尾一段，师傅可复制/拍照给客户）

固定骨架，3-5 句话，不用任何术语：

> 这台电脑的主要问题是 ___。我们已经 ___。建议 ___。没有删除您的任何个人文件。

约束：

- 「我们已经 ___」如实写：只做了诊断和预览，就写「只做了检查，没有动电脑里的东西」；执行了清理，要写明收回约多少空间（如「约 3.2 GB」）和删的是什么类型（临时文件 / 系统更新缓存 / 回收站等）。
- 「没有删除您的任何个人文件」这句必须原样出现。
- 不出现提交内存、SMART、WSD、注册表等术语；疑似硬件问题只说「建议师傅进一步检查」，不给客户下硬件死刑结论。
